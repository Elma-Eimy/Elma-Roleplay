## 范围与推进条件

M3 为现有个人生成入口增加导演，逐步判断知情、选择发言者和结束一轮。允许 A → B → A，也允许知情成员沉默。程序强制约束身份、调用预算、串行顺序和终态。

本稿给出实施方案；知情粒度、沉默协议和预算默认值仍须经 M3-A 原型验收。先验证核心互动，再实现正式编排，不以设计稿代替模型质量证据。M4 负责下一条用户消息确认、整轮候选重生成/切换和恢复；M5 负责继承事实检索、持续记忆与关系；M6 补完整交互。

M3 仍只执行一个未确认轮次，保留 version=1 和 can_generate=false。先通过独立临时数据原型观察自动互动，保存结果由现有只读详情展示；不增加手动选人按钮、不开放普通用户发送。原型必须能从真实内部编排入口执行到只读 HTTP，不能用手工拼接发言替代导演链路。

## 导演输入与角色输入

导演是内部编排职责，不建立额外 Persona。导演可读取有效群聊正文及其已记录知情范围，用于判断谁在场、谁听到内容和下一步是否值得回应。读取范围仅为此前已确认轮次的所选成功候选，以及本轮当前候选的已保存前缀；不包含兄弟候选、失败历史和未来轮次。

导演输入包含共同设定、用户昵称、固定成员 Persona ID/名称和有序内容。M3-A 检查角色卡结构后仅允许名称作为公开成员资料；description/personality 也可能包含秘密，不作为公开设定默认传入。全部角色卡、extensions、Prompt DSL、来源单聊、继承记忆、私人认知及自身状态 JSON 均不进入导演快照。若调度确实需要额外私人基线，须单独评估用途，不能通过导演向角色传播。

导演属于操作者层面的场景观察者，读取秘密正文不代表任何角色自动获知。其决定只能变成经校验的 Persona ID、visible/hidden 和结束代码。角色仍只接收 M2 装配的个人 messages；导演的理由、对未公开信息的概括和“你应该回应某秘密”等提示都不传给角色。

导演上下文按完整内容项截取，已确认历史在预算内取最近窗口；本轮前缀优先保留。预算不足以容纳本轮时明确失败，不静默删掉刚生成的关键场景。缺少依据的知情判断默认保守隐藏，不从成员 slot 或“固定成员”推断全员在场。截断提示只供导演使用，个人 Prompt 仍遵守 M2 的隐藏元信息边界。

## 判定阶段与结构化输出

采用四个职责阶段。初判只决定用户项知情；调度只决定下一位或结束；角色生成只产生自己的内容；后判为未公开正文决定接收者。导演初判与第一次选人分开，确保选择发言者时已有完整知情记录和可见依据。

| 阶段 | 输出草案 | 程序校验 |
| --- | --- | --- |
| user_visibility | `{"recipients":[{"persona_id":101,"decision":"visible"},{"persona_id":102,"decision":"hidden"}]}` | 覆盖固定成员且不重不漏，ID 属于本群，枚举合法 |
| next_action | `{"action":"speak","speaker_persona_id":101,"reason_code":"direct_response"}` 或 `{"action":"end","reason_code":"wait_user"}` | 严格区分联合形状，speak 目标属于可执行成员，end 不带发言者 |
| role_generation | 沿用 M2 的 reply/status/可选 state_update | 不允许角色改身份、接收者、调度或他人状态 |
| utterance_visibility | 与 user_visibility 相同的完整成员判定形状 | 作者必须 visible；全文粒度，禁止补入未经生成的摘要或改写正文 |

解析器拒绝未知字段、重复 JSON 键、重复成员、布尔冒充整数、非法枚举、额外文本和截断结果。失败即停止，不自动纠错重问、不用全员可见兜底。调度 reason_code 使用小型白名单，例如 direct_response、follow_up、wait_user；不接收自由文本理由或模型 reasoning。

调度可执行集合由程序根据当前快照的个人可见依据计算。导演只能在集合中选人；无依据的成员不能因为被选中就获得隐藏用户输入。集合为空时程序直接有界结束，不发起无意义的角色调用。不要求每名成员发言，也不禁止同一成员再次回应；达到上限后停止。

知情后判通过 M2 的异步回调接收作者与暂存正文，所需全局场景由编排快照提供。后判期间正文尚未公开落库。判定通过后，正文、自身状态增量、完整知情行和本步审计在同一事务提交；失败不保存半条发言。下一次调度只能读取已成功提交的前缀。

## 知情粒度与沉默的原型选择

第一版原型沿用整条全文 visible/hidden。单项混合公开台词与私密心理时，对旁听者保守隐藏全文；作者自身始终可见。程序不凭引号、括号或删词自动生成另一份正文。公开转述产生新项，旧秘密权限保持不变。

该方案会丢掉混合项里本可公开的台词，可能让旁听者无法自然接话。M3-A 必须对比纯公开、纯私密和混合内容。若关键场景因全文隐藏无法成立，暂停后续正式编排批次，补充可见单元设计：同一次角色输出明确拆成多个单元，各自保存正文和完整知情范围，并定义一次发言与多个内容项的映射、顺序、状态增量仅应用一次、预算按角色调用计数及兼容迁移。不能在现有全文项上临时追加“过滤摘要”掩盖问题。

沉默先由导演不选择该成员表达；不额外调用每名成员询问发言意愿。M3 原型暂不增加角色返回 silent 的协议，M2 的空回复继续视为失败。知情但沉默的成员仍有 visible 行，后续能读到内容；M5 再处理其成长。若真实模型经常被选中却无合理发言，优先检查调度输入与判断，再决定是否增加显式 silent，不能把空回复当正常结束。

### 可见单元修订与批次边界

M3-A 已证明全文隐藏无法保留混合项里的公开接话依据。本次先确定以下细分方案；M3-B 只落实与粒度无关的执行基础，继续使用 v1 全文协议，M3-C 先实现单元持久化再接导演审计。普通发送保持关闭，新的执行基础不作为全文粒度已通过的证据。

| 来源 | v2 单元方案 | 原文与身份约束 |
| --- | --- | --- |
| 用户输入 | 初判一次返回覆盖全文的有序 `[start,end)` 范围及逐单元完整接收者集合 | 范围使用 Python Unicode 码点偏移，连续覆盖且不重叠、不漏字符；正文仅从 Round.user_content 切片，不接受导演改写正文；前端不自行计算 UTF-16 范围 |
| 角色一次调用 | 输出单个 JSON 对象，含 units、status 与可选 state_update；每单元含 kind=speech/action/thought 和 text | 作者取服务端 Persona ID；最多 8 单元，均非空；导演后判一次处理全部单元，不能逐单元额外调用 |
| 单元知情 | 每单元对固定成员分别写 visible/hidden，缺行隐藏 | 角色自身全部可见；thought 只允许作者可见，其余单元仍按场景判断；公开转述是新单元，不改旧权限 |
| 状态与预算 | emotion、affection_change 和 state_update 归属一次调用的父发言项 | 所有单元和状态同事务保存，状态只重放一次；角色步数按调用计数，仍受 `3K+1` 总调用上界约束 |

M3-C 已新增内容项所属的单元与单元知情表，以候选/会话组合外键限制归属。用户单元保存原文范围，角色单元保存模型实际生成的文本；父内容项保留既有身份与轮内顺序，同一次角色调用的显示正文由其有序单元拼接，不能将每单元冒充一次独立角色调用。SQL 能表达的范围、枚举和唯一约束下推数据库，全文覆盖与跨单元完整性由服务事务校验。

个人读取先过滤单元再按原顺序组装获准文本，不附带隐藏单元数、位置间隙或摘要。作者的状态增量仍从父项按唯一来源重放，不能因 join 到多个可见单元重复累计。用户文本在个人输入中仅出现获准切片，不能再追加完整 Round.user_content；操作者只读视图仍能查看全文。混合用户台词与内心描述也要使用相同的范围和知情校验。

v2 的群聊最终输出契约必须完整替换现有群聊 XML 输出要求，不能在其后再追加互相冲突的 JSON 指令；角色卡 DSL、示例语义、原始用户切片与 PHI 后置继续保留。v1 历史和旧内部调用保留兼容，旧内容按原有完整知情结果作为一个单元迁入，不重新判断旧秘密权限。新单元不可原地改写，降级遇到无法保持原知情语义的 v2 数据时拒绝丢弃。

这些约束已在 M3-C 接入 ORM 和模型协议，并以旧库迁移、原子回滚、一次状态重放和混合用户/角色回归验证。离线固定单元证明 B 能看到“桥坏了”且看不到私密心理，真实模型误分类和自然度仍待验收。若模型将私密内容错标为 speech，程序过滤不能替代语义验收。

## 预算与模型选择

以下为原型建议值，尚未成为配置或产品承诺：每轮最多 K=4 次角色调用，内部可设 1–6；初判最多 1 次，调度最多 K 次，正文知情后判最多 K 次。完整执行的外部调用上限为 `1 + K + K + K = 3K + 1`，默认最多 13 次。第 K 次发言保存后程序直接结束，不再调用导演询问是否继续；提前 end 会替代其中一次调度并省去后续角色与后判调用。

所有阶段共用一个轮次预算对象，在派发前扣减；失败、取消、格式错误和超时均不返还额度。对实际网络请求数另做回归：SDK、适配层和编排器都不能隐式重试。现有适配层未显式设置 SDK 重试，因此仅统计 generate_async 次数还不足以证明调用上限；M3-B 必须补齐并验证群聊专用零重试调用选项。

原型另设整轮 300 秒截止时间，单次调用取配置的 LLM_TIMEOUT 与剩余时长较小值；预算在调用前、返回后和下一步前复核。超时先取消并等待当前调用和已派发数据库操作结束，再处理终态。截止时间约束新调用与生成等待，不承诺数据库线程强制终止或锁在第 300 秒立即释放。到达步数上限正常结束，超时或调用预算异常耗尽则失败，不能伪装成导演自然结束。

整轮起始冻结 provider、模型名、思考模式、思考强度、超时和输出上限；角色采样参数可按各自卡片读取一次并冻结，导演使用独立参数，模型保持相同。轮中修改全局设置不改变已启动任务。M2 目前仅传 model，不足以冻结全部设置；M3-B 扩展序列化调用快照并保留单步调用兼容。参数必须经现有模型能力解析，不能给所有模型硬塞不支持的 temperature 或 JSON 模式。

## 整轮执行权与状态收敛

新增内部 group_round_service 管理一轮，group_director_service 负责导演输入、协议和纯校验。执行入口名称待实现统一，不在本稿注册公开 HTTP 路由。

整轮在任何模型调用前取得既有数据库运行权引用和会话锁，并注册到应用拥有的任务集合。创建轮次、个人调用、知情后判、审计写入和结束均在同一执行权内推进。现有 prepare/append/finish/generate 的公开内部包装仍自行加锁；编排调用抽出的持锁步骤，不能调用这些包装造成冲突，也不能改为每步释放锁制造调度空隙。

执行权令牌绑定 Engine、session_id、任务与活动状态，只能由锁拥有者创建和传递；内部步骤验证令牌。不能接受调用方传 `already_locked=true`，也不能只以 lock.locked() 推断当前任务持锁。读快照和短写事务保持分离，模型与知情回调期间无活动数据库事务。

初判前只有内存中的用户原文；初判通过后原子创建 Round/Candidate/user 项、完整知情和初判审计。初判失败不创建残缺轮次，原型返回非敏感错误码。轮次创建后每次提交均检查候选 generating、归属及 expected_revision；审计或终止原因写入同样参与版本推进。提交结果不确定时只核对本次操作状态，不重新调用模型。

| 结束情况 | 持久化与后续行为 |
| --- | --- |
| 导演 end、无可执行成员或达到角色步数上限 | awaiting_confirmation，记录 wait_user/no_visible_basis/step_limit；零发言也允许正常结束 |
| 导演或角色格式错误、外部调用异常、后判失败、超时 | failed，记录阶段错误码；保留已提交前缀，不确认、不提纯、不自动续接 |
| 取消发生于已派发写入期间 | 等待线程结束；以真实提交结果保留前缀，再尽可能标失败；不回滚已经提交的成果 |
| M3-A 原型最终终态提交明确成功后收到取消 | 以已提交终态为准，返回完成结果及新 revision；不再传播取消或改写成功候选 |
| revision 已变化或候选被结束/删除 | 丢弃迟到结果，不覆盖新的状态；失败标记也必须版本复核 |
| 进程退出遗留 generating | 沿用启动中断处理标 failed/process_interrupted，不恢复或重发 |
| 失败标记因数据库不可写而失败 | 保留原始错误/取消，日志仅记录异常类型；由后续启动收敛 |

关闭流程先禁止新任务，再取消并等待所有群聊轮次任务和持久化，最后释放运行权；重复取消也必须等待清理。M3 原型持有同样运行权并声明单 Worker。M4 完成前，失败轮次继续占用未确认轮次限制，不开放第二轮绕过恢复。

## 审计与数据交接

M3-C 已新增候选所属的 group_director_steps，保存 stage、step_index、预期与提交 revision、发言者 Persona ID、关联内容项 ID、规范化 decision_json、reason_code、模型名和策略版本。decision_json 仅保存通过严格校验的成员判定或动作；不保存原始模型输出、reasoning、自由文本理由、完整 Prompt 和凭据。预算消费及耗时可记录在内部诊断中，不能据此重放请求。

表归属使用 session_id/candidate_id 组合外键，内容引用限制在同候选，发言者限制同群；候选删除级联清理审计。明确 `(candidate_id, step_index)` 唯一和阶段形状约束。Candidate 预留独立 finish_reason，区分正常停止与 failed.error_code；不将正常步数上限写成失败。实现时从实际 Alembic head 新增迁移，同时更新 ORM，非空审计/终止信息降级需保护，不覆盖 M2 的已有 revision。

初判审计与用户项、知情后判审计与发言项、调度 end 与候选终态分别原子提交。下一发言者决定在模型调用前保存并推进 revision；失败保留已接受的调度，不据此自动重跑。对未通过校验的响应只记录非敏感阶段错误码，不能保存未验证 JSON 为下一次 Prompt。

审计不进入普通 rounds 响应、角色个人历史、世界书扫描或记忆提取；只供隔离原型与内部检查。M3 不新增“导演状态”用户面板。完整交接给 M4 的是候选 ID、revision、终止原因和保存前缀，而非另一套轮次身份。

## 隔离原型与验收矩阵

M3-A 先提供可执行的离线回放入口，严格复用计划中的导演解析、个人生成和暂存后判边界；允许独立配置显式启用真实调用。仅生成虚构临时数据库和媒体目录，不复制开发库、来源近期聊天或真实个人资料。在线配置在进程外提供，不入库、不写报告。真实调用需明确授权，当前设计推进不等于已经执行或批准费用不明的在线评测。

原型一次执行一轮，已确认历史由虚构夹具建立；不通过直接确认开发库轮次演示多轮。保存结果后由临时只读后端供现有详情页查看，或导出不含凭据的本地报告。报告区分程序断言、模型判定人工评审与界面/真机结果；假模型不能证明导演判断准确。

| 场景 | 必须检查的结果 |
| --- | --- |
| 用户与 A 独处，B/C 不在场 | 导演可看到秘密，B/C 最终 messages、世界书与查询输入均不含秘密；错误知情判定单独计为模型失败 |
| B 旁听但沉默，后来回应 | 不强制 B 发言；visible 行保留，后续个人输入含获准内容 |
| A → B → A 与立场冲突 | 可重复选 A，顺序及自身状态正确；人工评估是否自然、是否重复附和 |
| 当前用户项对 B 隐藏但 A 公开转述 | B 只见新转述，原始秘密项不被追改为可见 |
| 同名成员、伪造标签和提示注入 | 身份取校验后的 Persona ID；正文/导演理由不能改写归属或绕过集合 |
| 混合公开台词与私密心理 | 保守隐藏不泄漏；记录公开信息损失是否阻断关键接话，决定是否升级可见单元 |
| 空可执行集合、导演立即结束 | 零角色调用且有明确终态，无无限选人或虚假台词 |
| 永远继续、格式错误、模型超时 | 程序预算生效，实际请求数有界，不自动修复重问；保留可检查错误码 |
| 后判/审计提交失败、取消与版本竞争 | 不公开半条内容；正文、知情、状态和审计一致，锁最终释放，迟到结果不追加 |
| 轮中改设置、关闭与第二进程 | 模型参数冻结；关闭等待全部任务后释放运行权；另一进程不能接管运行中的数据库 |
| 兄弟候选、失败历史与未来轮次 | 导演与个人上下文均遵守各自读取范围，不能从操作者列表直接拼输入 |
| 只读展示与旧单聊兼容 | 整轮状态、身份、失败前缀可读；无手动调度，单聊 Prompt、流和事务行为不变 |

在线样本至少覆盖上表前六个语义场景，每个记录预期知情和人工判定；出现秘密泄漏必须定位为导演误判或输入过滤缺陷，不以总体平均分掩盖。自然度、沉默与全文粒度的通过标准在 M3-A 报告中写出具体成功/失败例，未实测前保持待验收。
