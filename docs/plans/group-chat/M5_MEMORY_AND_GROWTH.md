## M5-A 已接入成员继承记忆

群聊创建时已冻结每名成员的有效记忆。新候选在角色生成前，用该角色当前的承接依据查询其专属 SQLite 快照。缺少明确依据时使用个人历史窗口末尾最多三条中的本轮可见正文，以及面向该成员的待回应请求。连续片段分别取词，隐藏间隔两侧不能拼成查询词。查询与个人历史使用同一读事务。返回内容进入本人 Prompt，导演和其他成员不会直接收到这份资料。公开讲出的往事仍按新发言的接收者规则传播。

本批选择本地词项匹配，便于先验证身份和候选边界。中文使用相邻双字，其他文字使用至少两个字符的完整词，忽略大小写。每段查询取前 2400 字符，按共同词项数量、重要度和快照编号降序选择最多三张卡。单卡正文上限 1000 字符，超长卡跳过，以免截断否定语句或条件。传递正文、类型、时间状态和时间附注。没有匹配时不注入。规模成本随该成员符合长度条件的卡数增长，同义改写和单字线索可能漏召回，通用词也可能误匹配。

[召回服务](../../../app-backend/services/memory/group_memory_recall.py)只读取快照。新持久候选把启用标记写入调用参数；旧持久候选缺省关闭。重生成使用新候选自己的上下文，续接沿用原候选的策略。无需回填业务表，HTTP 请求和响应沿用现有契约。

## 验收

[隔离回归](../../../app-backend/tests/conversation/test_group_memory_recall.py)通过正式后台接受、两次角色生成和终态提交，校验已冻结的时间信息、来源删除、未确认来源排除、导演与成员隔离。另覆盖不连续的可见片段、有效新线索及旧策略缺省关闭。

2026-11-06 用虚构单聊和迁移后的临时 SQLite 走正式 HTTP 路由，在群聊创建后删除来源记忆，再用 deepseek-v4-flash 完成一轮、8 次真实调用。两名成员均实际生成；原持有人收到铜铃刻字，原卡成员的实际输入没有刻字。一轮样本只用于确认调用链和本场景的输入隔离。

## M5-B 已确认轮次的成员提纯

发送下一条用户消息时，后端在同一事务内确认上一轮、为采用候选中有可见内容的成员登记任务，再接受新轮次。最新未确认轮次、撤回和重生成操作都不派发提纯。旧库升级只创建表；升级后的首次确认可以处理先前留下的未确认轮次，已经确认的历史不自动补跑。

[群聊提纯服务](../../../app-backend/services/memory/group_memory_capture.py)按知情记录读取成员的证据。v2 使用可见单元，心理限作者，用户的推进请求和私人心理不作为事实输入。v1 沿用已有整项授权。无需成员发言，只旁听也能形成记忆。每名成员每轮最多写入四张卡，每张含类型、时间状态、内容、证据引用及引文。服务校验引文确实出自该成员可见的对应记录；内容概括是否忠实仍取决于模型。

群聊后台任务使用配置的记忆模型，SQLite 保存任务与结果。候选、轮次和成员通过组合外键限制在同一群；每轮每成员唯一。模型调用期间释放数据库事务；成功时一次写入整组卡，无值得保留的内容则写入空数组。失败退避重试，进程中断后领取期限为十分钟。过期尝试的结果不能覆盖后来领取者的结果。删除整个群聊时，已形成的卡和待办一并回收。升级后的数据由独立表保存，遇到任务或结果时拒绝有损降级。

[成员提纯回归](../../../app-backend/tests/conversation/test_group_memory_capture.py)覆盖确认回滚、同轮重生成后只取采用候选、沉默与私密片段、引用不合法、重复执行、租约过期和执行中删群。[迁移回归](../../../app-backend/tests/infrastructure/test_group_capture_migration.py)检查旧库、唯一约束、跨群写入及级联删除。

2026-11-06 使用虚构三人群和临时迁移库，通过正式 HTTP 发送两轮并运行后台提纯。deepseek-v4-flash 完成 7 次群聊调用与 2 次提纯调用。发言者形成 3 张卡，包含只写在她掌心的编号；沉默旁听者形成 1 张关于铜铃公开存放点的卡，其模型输入和结果都没有私密编号。缺席者没有任务。本次仅验证该场景，跨轮去重、认知更新和新卡召回分别在后续批次处理。

## M5-C 已接入个人认知与关系印象

后台在同一次提纯调用中提交本人的性格、继承认知、该候选起始时可用的个人印象及本轮可见记录。模型可返回空数组，也可形成最多四条认识。每条引用一个可见片段并附原文。个人认识可描述一次改变想法的经历；关系印象有方向，对用户的印象须引用明确标记为用户台词的片段，对群成员的印象须引用该成员本人的可见言行。例如，旁听者可以因一名成员替人澄清而更信任这名成员。角色对用户的数值好感仍按发言增量重放。

[个人印象投影](../../../app-backend/services/memory/group_member_insights.py)按故事轮次保留最近四条个人认识，每个关系对象取最近一条印象。重试产生的旧轮结果按原轮次排序。候选在接受事务内冻结已写入的结果编号上界；同一候选生成和续接期间，即使后台刚刚完成提纯，其输入范围也保持一致。校验失败时会把错误条目反馈给模型，允许一次修正。修正后仍无依据的单条印象会被过滤，任务记录 insights_filtered；记忆卡不合格时仍退避重试。通过校验的新认识与记忆卡一起提交，过期执行者不能补写印象。旧候选及升级前已完成的提纯没有认知结果，不自动重跑。

2026-11-06 使用临时 SQLite 重放真实群聊中“用户承认偷铃并栽赃岑夏”的已确认轮次，以 deepseek-v4-flash 重新提纯，再通过正式 HTTP 接口发送下一轮。岑夏保存了对用户和对陆遥的两条不同印象，逐字核对后续四次群聊调用，两条印象仅出现在岑夏的角色输入。陆遥的关系推断未通过引用校验，保留了三张通过格式与引文校验的卡；缺席的周宁没有该轮任务。引文校验只能核对来源，例如模型仍可能把陆遥开口前“我一直没说话”概括成整场沉默。

## M5-D 成员记忆的统一召回

候选接受时保存当时可用的卡片编号上界。角色发言只读取自己的入群快照和更早已确认轮次中采用候选的提纯卡，重生成重新确定上界，旧候选续接沿用旧策略。升级迁移为已有快照和已完成提纯分配编号、登记索引任务。正在执行的候选可以继续按原有入群快照策略生成。

[统一召回服务](../../../app-backend/services/memory/group_memory_index.py)对每个可见片段分别匹配词项，从最长的连续片段发起一次语义查询。Chroma 按成员和编号上界返回至多八个编号，余弦距离上限为 0.50。SQLite 再按轮次、采用候选和归属读取正文。向量就绪程度影响排序；查询失败或索引待建时可仅按词项召回。最多向本人提供三张卡，单卡上限 1000 字，保留入群或群内来源、时间状态和群内发生轮次。

正文去除首尾空白后，类型、时间状态和时间附注也相同的卡合并展示。提纯时给模型最多三张本人的相关旧卡供对照。只有新引文明确更正同一事实或取消同一计划，才允许在新卡上引用提供过的旧卡编号。含多个标点分句的旧卡暂不作为整卡覆盖目标，以免丢失仍有效的细节。修正生效后，旧卡及与其等价的早期副本从该成员后续候选的视图隐去。继承快照原文保留。服务能验证引用、归属与发生顺序，是否确属同一事实仍依赖模型判断。

群聊索引使用独立集合 group_memory_v1 及 gc_ 编号，SQLite 保留来源和覆盖关系。写入和级联删除在同一事务登记 Outbox；任务重试重读 SQLite，已删除的卡即使迟到写入也会清理。可在后端目录运行 `python -m scripts.rebuild_group_memory_index` 登记重建，后台从 SQLite 恢复群聊集合。库中仍有召回卡、关联索引任务或使用该编号上界的候选时，迁移会拒绝降级。

### 隔离实测

- 使用 deepseek-v4-flash 提纯“原定交给青鹭的安排已经取消，现在只由赤羽保管”。模型返回带有连续引文和旧卡编号的新事实。新建候选的角色输入中已无旧卡的 Q17 标识。该样本用固定导演和角色响应单独观察提纯与提示词变化。
- 使用配置的 doubao-embedding-vision-251215 和临时 Chroma 实测两张虚构卡。“搭航班”命中“害怕乘坐飞机”，余弦距离约 0.488；“开锁用的东西塞在哪个把手中”命中“钥匙被藏在雨伞的握柄里”，距离约 0.428。球队比赛问题返回空。这三个问题用于核实调用链和当前阈值，未测出普遍的查准率。另在真实临时 Chroma 中重建两张卡，核对重建前后编号相同，删群并执行清理后集合内文档数为零。
- 临时 SQLite 含 10002 张个人卡时，五次本地词项回退读取为 231–270 毫秒，不含 Embedding 网络耗时。该路径逐卡匹配，数据量继续增长时成本会随之增加。[群聊召回回归](../../../app-backend/tests/conversation/test_group_memory_recall.py)覆盖采用候选、个人输入、重复旧卡、更正、重建和迟到写入清理。
