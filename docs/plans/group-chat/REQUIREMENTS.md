## 目标体验

一个用户与最多三个 AI 角色共同演绎场景。角色可以说话、行动、观察，并保持各自立场。用户主要扮演固定人物，也可以描述环境；事件也可以由角色推动。

灵感来自用户体验过的 Grok bot 多角色群聊，本文不依赖其具体实现。目标是自然接话，而非每个角色轮流回答同一句问题。例如用户质问 A，A 解释，B 指出矛盾，A 再回应 B，C 可以保持沉默。应避免重复附和和角色全知。

自然互动优先于极低延迟。允许逐个生成和短暂等待；不预设统一回复长度。沿用角色卡的用户自主权约束，不另行堆叠重复要求。

## 已确认范围

| 主题 | 首版要求 |
| --- | --- |
| 参与人数 | 包括用户最多四人；仅一个真人用户，不涉及多人真人在线协作 |
| 群成员 | 创建后固定，不提供成员增删和复杂进退场、位置管理 |
| 发言控制 | 全自动选择发言角色，不要求用户点名；允许同一角色在一轮中多次回应 |
| 推进方式 | 串行生成，不做抢话、并行发言或生成中插入用户消息 |
| 有限互动 | 每轮有程序强制执行的最大步数；可提前结束并等待用户 |
| 模型 | 首版统一模型；导演与角色通过不同调用职责及上下文区分 |
| 共同设定 | 可选，有共同设定时优先；为空时沿用角色背景，允许角色保留原世界背景 |
| 人格来源 | 从原始角色卡开始，或继承某段单聊的认知、长期记忆及相关人格状态；不带入近期对话 |
| 人格成长 | 各成员拥有群聊专属 Persona，持续更新认知、长期记忆、好感度和关系 |
| 关系 | 支持角色之间的独立关系，不仅是角色与用户的关系 |
| 候选 | 整轮重新生成、整轮候选切换；下一条用户消息确认上一轮，确认后不可切换 |
| 界面 | 支持状态面板和立绘，发言归属清楚 |
| 暂不提供 | 群聊创建故事分支、语音、手动发言调度和主动打断生成操作 |

群聊人格可以正常形成新的长期记忆。暂缓的是“从群聊再创建故事分支”的产品操作，不是记忆成长，也不是内部人格继承能力。

## 幕后导演与角色生成

采用轻量导演编排作为当前设计方向，不要求引入通用 Agent 框架或独立常驻角色进程。导演不是额外群成员，也不是必须配置另一款模型的“第五个角色”。

导演查看当前有效群聊场景，判断知情范围、选择下一位发言者，并决定继续或结束。每次只决定下一步，不预先编排整轮台词。角色生成器使用自己的设定、可见历史、认知、记忆和状态生成实际台词与行动。

```text
用户消息
  → 导演判断知情范围与下一位发言者
  → 为该角色装配独立上下文
  → 生成并保存发言及关联状态
  → 导演根据新发言再次判断
  → 提前结束或达到步数上限
  → 等待下一条用户消息确认本轮
```

程序负责步数限制、身份校验、持久化和终态，不能依赖模型自行遵守。调度结果应可检查，便于排查错误知情、重复接话和不合理沉默；不要求在日常聊天界面展示内部诊断。

首版不要求每个角色再单独调用模型判断发言意愿。是否允许被选中的角色返回沉默，留待协议设计和场景验证决定。导演只传递必要调度信息，不能通过包含秘密的理由向角色泄露不可见事实。

## 知情与沉默

“系统能够读取群聊内容”与“角色本人知道内容”必须分开。用户原始设想是各角色可临时查看场景来判断参与，但不自动将全部内容留下；采用导演后，由导演承担全局判断，角色扮演调用只接收获准知情的部分。

| 情况 | 个人上下文 | 记忆与状态 |
| --- | --- | --- |
| 不知情 | 不加入该段原文 | 不据此生成个人记忆或变化 |
| 知情但沉默 | 保留可见内容 | 确认后可进入记忆提取；是否发生状态变化按业务规则判断 |
| 知情并回应 | 保留可见内容和自身发言 | 正常处理已确认内容及状态 |

例如用户和 A 逻辑上独处，B、C 虽然仍属于固定群成员，也不应获得该段剧情知识。若 B 在旁听，则沉默不等于不知道。首版不实现完整空间系统，由场景语义判断这种差异。

不能在同一次模型调用中先暴露秘密，再宣称已从上下文删除。隔离应落实到生成输入和后续历史选择。后来的公开转述可以构成新的知情来源，但不能因此开放原先整段秘密历史。

导演判定本身存在模型误差，需要真实场景验收；程序保证的是按已记录的知情范围过滤，而非保证模型永不误判。

## 人格继承与长期记忆

每个群聊成员建立新的 Persona，可以拥有不同的单聊来源。继承起点必须固定：原单聊后续发展不能扩大群聊可见范围，群聊成长也不能回写原单聊。

沿用现有人格独立、记忆归属及来源边界的思路。[M1 设计](M1_DATA_AND_PERSONAS.md) 选择创建时冻结来源单聊当前已保存状态与有效记忆，不复制整库、不复制近期聊天，也不建立动态祖先读取链。由于认知等缺少完整历史版本，首版不承诺任意旧消息时点的人格还原。无来源的成员从角色卡初始化。

群聊内的新记忆写入对应成员 Persona。只有下一轮用户消息确认的 active 轮次才能进入提纯，且提取输入必须按成员知情范围过滤。同一段对话可以被不同知情成员分别理解和记忆；不知情成员不能通过认知摘要、事件缓冲、图谱或检索间接获得它。

既有单聊记忆可以读取，但不带近期聊天原文。好感度、角色状态、认知与关系的具体继承字段，需要逐项映射并验证。角色间关系的数据表示、方向性和面板展示仍待设计。

## 整轮候选与一致性

一条用户消息触发的全部角色发言构成一轮。候选一可以是 A → B → A，候选二可以是 C → A；两者是完整替代版本，不是互相并存的发言集合。

重新生成应从同一轮前状态开始。切换候选时，消息、知情记录、各成员状态、关系和立绘关联须保持同一版本，不能留下另一候选的派生结果。下一条用户消息确认上一轮，此后不再切换该轮。

导演判断和部分发言已经落库、后续生成失败时，如何展示、保存与继续，需要单独定义。不能直接沿用单聊“失败清理用户消息”的逻辑，也不能靠重复聊天 POST 恢复流式接收。无角色回应的情况不作为主要产品流程，但必须能有界结束。

## 现有实现与改造边界

以下为评估时的代码入口，不是已完成的改动。

| 当前基础 | 群聊设计需解决的问题 |
| --- | --- |
| [ORM](../../../app-backend/core/models.py) 的 Session 与 Persona 一对一 | 支持多成员及各自继承起点；不能仅移除唯一约束而忽略调用方 |
| ChatMessage 的 user/assistant 与候选 parent_id | 明确发言成员、轮次、轮内顺序、整轮候选和知情记录 |
| [回合服务](../../../app-backend/services/conversation/chat_turn_service.py) | 从单次回复扩展为有限多步编排，处理部分成功及失败清理 |
| [上下文装配](../../../app-backend/services/conversation/context_assembler.py) | 允许看到本轮此前的有效发言，并按成员过滤；保留继承边界 |
| [记忆提取](../../../app-backend/services/memory/memory_extraction_service.py) | 显式指定成员 Persona，避免通过会话查找唯一人格；核对相关事件、认知和图谱链路 |
| [聊天 Store](../../../app-frontend/src/store/chatStore.ts) 与 [流协议](../../../app-frontend/src/utils/chatStreamProtocol.ts) | 区分单条发言完成和整轮完成，多角色消息归属、恢复与迟到回调隔离 |

继续使用现有 SQLite、ChromaDB 检索索引、模型客户端与 Outbox，不因群聊默认引入新基础设施。保持现有单聊行为兼容，数据变更提供 Alembic 升级路径。

## 模块实施入口

这是跨数据、生成、记忆与三端界面的较大项目。需求与业务边界以本文为准；模块依赖、进度、下一步和交付证据统一维护在[群聊模块实施计划](README.md)，不在两处重复维护状态。

| 模块 | 交付内容 | 完成依据 |
| --- | --- | --- |
| M1 群聊数据与人格基础 | 群聊创建、固定成员、独立 Persona、共同设定与继承起点 | 创建读取正确，迁移兼容旧库，单聊不受影响 |
| M2 单角色发言与知情隔离 | 发言归属、个人可见历史、独立 Prompt | 角色只使用有权知道的内容，轮内历史顺序正确 |
| M3 导演与有限互动 | 知情判断、下一发言者、串行推进和结束预算 | 自然接话、合理沉默、有界结束 |
| M4 整轮候选与失败恢复 | 整轮重生成、候选与状态恢复、部分失败和断连续接 | 无候选残留、重复生成或确认后切换 |
| M5 记忆与人格成长 | 继承记忆读取、新记忆提取、认知、独立关系及检索边界 | 无秘密泄漏、来源单聊回写或失效候选污染 |
| M6 完整界面与联合验收 | 候选操作、状态面板、立绘、三端体验和真实模型验收 | 产品场景与一致性要求达标 |

每个模块先设计边界，再分小批实现并验证。前端随 M1–M3 提供最小可观察入口，不等后端全部结束后才接入；M6 负责完整交互和联合验收。M2–M3 先验证互动核心，原型中的临时简化不代表缩减首版范围。

先前讨论的人日数仅为初评，不作为排期承诺；群聊持续记忆已经明确纳入首版，应在详细设计后重新拆分估算。真实模型验收使用独立配置与数据，不直接写删开发库。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 用户与 A 逻辑上独处 | B、C 的生成输入、记忆及认知不含该段秘密 |
| B 旁听但不回应 | 下一轮仍能基于听到的内容回应，不因沉默丢失知识 |
| A 发言、B 接话、A 再回应 | 顺序上下文正确，允许再次发言但不无限推进 |
| 三个角色立场不同 | 不强制人人回答，不重复附和；具体自然程度需人工评估 |
| 成员分别从不同单聊继承 | 各自起点正确，原单聊后续内容不泄漏，群聊不回写 |
| 新角色从原卡开始 | 不获得其他成员的私人历史 |
| 整轮重生成与切换 | 消息、状态、知情范围及立绘一致恢复；确认后禁止切换 |
| 已确认群聊形成记忆 | 按成员可见内容提取，未确认或失效候选不进入长期记忆 |
| 导演格式错误、全员沉默或达到上限 | 有界退出，不产生无限调用 |
| 中途失败、断连、切故事或切服务器 | 无重复生成、错误回滚或旧回调覆盖新状态 |

实现时遵循[协作约定](../../../AGENTS.md)执行相关隔离测试、完整后端回归及受影响的三端构建。真实模型的互动质量不能由 Mock 或构建成功代替。
