## 范围与设计状态

M1 提供群聊创建、列表、详情和完整删除，建立固定成员、独立 Persona、共同设定与来源单聊快照。最小前端可创建和查看群聊，不提供尚未实现的发送能力。导演、生成、候选执行和持续记忆提取由后续模块实现。

## 选定方案与取舍

| 决策 | 方案及理由 |
| --- | --- |
| 会话容器 | 复用 sessions，增加 single/group 类型，共享故事 ID 与锁；旧列表显式筛选 single |
| 人格归属 | 一个 group Session 直接拥有多个 Persona，不建立隐藏单聊；复用人格级状态、任务和本地记忆归属 |
| 成员身份 | Persona ID 即稳定成员 ID；任何操作仍校验其 session_id，不另建第二套成员 ID |
| 来源继承 | 创建时冻结有效状态和记忆，不把群聊 Persona 接到来源 parent_persona_id 链；避免来源修改与删除改变群聊 |
| 单聊分支 | 原父会话、父人格和分叉点机制保持；群聊不进入该路径 |
| 删除角色 | 被任一群聊使用时拒绝删除，提示先处理群聊；避免静默删群或残缺成员 |
| 导入时间 | 首版导入创建时单聊当前已保存状态，不提供任意旧消息时刻的人格还原；认知摘要没有完整历史版本 |
| 开场 | 初始群聊不插入各角色 first_mes，避免多个开场冲突；M2/M3 后由首条用户输入推动 |

不可变导入快照是相对现有分支的实现差异：复用人格与记忆视图的概念，但不直接复用动态祖先读取链。代价是复制有效记忆的存储空间，以及 M5 需要将快照接入统一检索。

上述是设计默认选择，不冒充用户逐项确认的新增需求。若要同卡多实例、历史时刻导入或删除角色后保留群聊，先修订设计再实施。

## M1 持久化结构

### 会话与成员

| 字段/约束 | 定义 |
| --- | --- |
| sessions.kind | 非空，默认 single，CHECK 为 single/group；旧行均 single |
| sessions.shared_setting | group 可空文本，空白归一为空，首版创建后固定 |
| sessions.user_nickname | group 创建时保存；single 继续使用现有昵称传参逻辑 |
| group 的 parent_session_id、fork_message_id | 必须为空，成员各自的来源另存 |
| session_personas.member_slot | 非空；single 为 0，group 为 1–3；数值 CHECK 为 0–3 |
| UNIQUE(session_id, member_slot) | 替换 session_id 唯一约束；稳定 slot 不代表发言顺序 |
| UNIQUE(session_id, character_id) | 首版同一角色卡不能在一个群聊中重复加入 |
| Persona 动态列 | 各成员独立保存好感、心情、认知、场景、状态基线和立绘；进度指针初始化为空 |

群聊 Persona 的 parent_persona_id 固定为空。single 只能 slot 0、group 只能 slot 1–3、创建成员数和来源角色匹配属于跨表规则，在统一创建服务事务中校验。数据库数值约束与联合唯一限制可占用位置，不对外提供逐个增删成员接口。

创建建议要求 2–3 个 AI 成员；下限属于本设计选择，可以在实现前改为 1–3，不影响结构。最多三个 AI 是已确认需求。用户不是 Persona，由 Session 的用户信息表示。

ORM 使用 `Session.personas` 作为唯一可写集合并承担级联。`Session.persona` 保留为只读兼容访问：single 返回 slot 0，group 返回 None。旧服务通过单聊资源加载器检查类型，不能靠 None 异常处理群聊。不要同时保留两个重叠的可写关系；实现时扫描原来的关系赋值及测试夹具，迁移为显式插入或集合赋值。

### 起点与继承记忆快照

新增 `group_persona_origins`，每个群聊 Persona 一行，persona_id 为主键及 CASCADE 外键。原卡起步也记录。字段包括 mode（card/single_snapshot）、snapshot_version、captured_at、initial_state_json、来源故事与人格 ID、source_last_active_message_id、source_confirmed_before_id、内容指纹。

来源 ID 与边界是审计整数，不使用会随来源删除而置空的外键，也不参与实时继承。读取详情可另查来源是否仍存在；来源删除不重连群聊，不删除快照。

initial_state_json 是经过版本和形状校验的不可变基线，含已解析的角色状态、好感、心情、认知、场景与立绘选择。Persona 的动态字段后续可成长，起点不随之覆盖。来源状态中的角色间关系不能直接按名字映射成本群关系；保留认知文本，结构化关系初始化由 M5 明确目标身份。

新增 `group_inherited_memory_snapshots`，至少包含主键、接收 persona_id（CASCADE）、记忆类型、正文、重要性、时间语义、来源记忆/人格/故事 ID、来源消息上界与内容指纹。UNIQUE(persona_id, source_memory_id) 防止重复导入；来源消息 ID 不能被解释成群聊本地消息 ID。

快照取创建时有效记忆视图中未被隐藏的卡，包括有效整理摘要。不复制原对话、来源任务、事件缓冲、整理操作和扫描进度。快照是有来源的继承事实，不伪装成群聊手工无来源记忆。缺失立绘按现有规则降级，不复制来源消息 ID 作为目标选择。

M5 将快照与本地 MemoryChunk 合成统一事实视图，支持列表、检索、去重、认知和图谱证据。快照只读，修正采用本地覆盖关系，不能修改来源或起点。索引同步沿用 Outbox，但快照必须使用独立 ID 命名空间，不能复用原 mem_{id}；具体载荷在 M5 设计。M1 只冻结交接数据，不调用 Embedding，也不宣称检索已经接通。

## 导入与事务一致性

来源必须是同角色的单聊；群聊来源拒绝。导入的是创建时当前 active 状态，包括尚未由下一轮确认的当前候选即时状态，不提供任意旧时点还原。认知按已保存值复制，不调用模型重新总结。

记忆使用来源 Persona 当前有效视图，同时按已有祖先分叉边界过滤；本地有消息来源的卡排除未确认范围，真正无来源的手动卡按有效视图保留。尚在后台处理但没有保存的记忆不进入快照，以后也不自动补入。界面文案明确“导入当前已保存状态与记忆”。

创建顺序：验证请求 → 按来源 session_id 升序取得会话锁 → 同一 SQLite 事务内重新检查来源与角色 → 读取一致的状态及有效卡 → 插入 Session、全部 Persona 和快照 → 提交。来源正在生成时拒绝；锁按序释放，失败整体回滚。

Python 会话锁不足以隔离后台写入。实现须按仓库事务约定使用同一数据库快照和写入串行策略，避免混合读取提纯前后的内容。外部模型、向量和文件处理不得位于事务中，不能中途提交一个成员。批量读取可以减少内存，但不能为分页切换数据库快照。

不静默截断记忆数量。实现时用大样本测量一次性复制耗时；若需要异步导入，必须设计持久创建状态和恢复，不能把半成品群聊当成功结果返回。

## 后续模块共用边界

M1 不提前建立全部未来表，但下面的身份、版本与状态语义必须保持。

| 概念 | 约束 | 实现责任 |
| --- | --- | --- |
| Round | 一条用户输入对应一轮，归属 group Session；不能从最后一个 assistant 推断完成 | M2 建立最小归属，M4 完善生命周期 |
| RoundCandidate | 归属 Round，表示整段发言及状态的版本，最多一个当前选中版本 | M4；M2 初始生成须能归入初始版本 |
| Utterance | 归属候选，带 speaker_persona_id 与轮内顺序；成员和候选必须属于同一 Session | M2 |
| Visibility | 归属候选和具体内容，按接收 Persona 记录；缺少判断不得默认公开 | M2 定义，M3 生成判断 |
| 状态/关系增量 | 归属候选及接收 Persona；对方是本群 Persona 或明确的 user 类型，不用昵称当标识 | M4/M5 |
| Confirmation | 新用户消息接受与上一轮确认原子化；仅确认的选中版本进入提纯 | M4/M5 |

同一轮的 A、B 发言不能当成现有 parent_id 的互斥候选兄弟。不能仅凭 is_active 表达全部群聊状态。用户原文可以归属 Round，但该内容的角色可见判定仍需按候选版本保存。

生命周期至少区分生成中、结束待确认、已确认、失败待处理；具体枚举和恢复转移留给 M4。失败和候选切换均不等于确认。M4 完成前不开放依赖未实现恢复机制的操作。

## 旧入口、删除与资源安全

所有单聊路径显式限制 single：聊天、历史、分支、消息编辑/删除、候选、状态、立绘、记忆、认知、Prompt 及 TTS。message_id 入口先解析所属会话。后台任务也检查会话类型，M5 完成前不得为 group 入队。

实施前全文扫描 `session.persona`、`SessionPersona.session_id`、`parent_persona_id` 和批量删除，逐项记录处理结果；不能只修 sessions 路由。CHARX 更新、角色删除和素材回收的引用也需核对。

群聊删除收集全部成员本地数据及资源，在同一事务删除聚合并登记 Outbox，登记失败整体回滚。只清理本群资源，不修改来源故事、不重连源祖先。生成中的删除行为由后续生命周期约束，M1 先采用同一会话锁入口。

被群聊引用的 Character 在任何删除写入前返回 409；仅关联单聊的删除保持原行为。来源单聊删除后快照仍可读。

角色卡本身不在 M1 冻结，设定编辑沿用既有角色卡语义。冻结的是运行人格和导入记忆。若未来要冻结完整角色卡，需同时处理世界书与素材，不只复制正文。

### M1-B：来源快照与群聊聚合服务

`services/conversation/group_session_service.py` 提供内部创建、列表、详情和删除；输入采用不可变的 GroupSessionDraft/GroupMember，不接受任意状态 JSON。成员数为 2–3，角色卡不重复；标题与昵称为 1–50 字，共同设定最多 20000 字，空白归一为空。服务响应返回 can_generate=false，列表不含记忆正文。HTTP 请求模型与前端领域接入随后由 M1-C 完成，见下文记录。

创建先按来源故事 ID 升序加锁，在同一 BEGIN IMMEDIATE 写事务中重读来源，冻结当前 active 状态、认知、立绘及已保存的有效记忆。记忆沿用 memory_view，保留祖先分叉边界、无来源手工卡与有效整理摘要，排除当前未确认的本地消息来源。失效立绘回退头像；不复制原消息、任务、事件缓冲、进度或 parent_persona_id，不调用模型或 Embedding。

`group_persona_origins` 保存初始状态、版本、审计来源和内容指纹；`group_inherited_memory_snapshots` 保存继承事实及时间语义。来源字段均不设外键，来源编辑、删除或撤销整理不改变群聊快照；这些表没有编辑入口，后续修正与统一读取由 M5 设计。新迁移接在 M1-A 之后，降级遇到非空快照表即拒绝，不能以移除快照方式保留群聊。

整群删除与 Outbox 登记处于同一事务，覆盖全部成员、本地记忆、事件、任务和图谱。只登记本群向量文档与未被其他故事引用的音频，不删除角色、立绘、来源记忆或来源故事。角色删除也采用 BEGIN IMMEDIATE，等待正在创建的群聊提交后重新检查引用，防止“检查时未引用、删除时已加入”的竞争。

请求取消后等待数据库线程结束再释放来源锁；已经派发的原子创建可能成功提交，但结果不再交付。M1-C 不得因此自动重发 POST，本批未提供持久幂等请求 ID。锁只在本次操作内持有，跨事务仍重新加载数据。群聊专用资源服务用 group_session_operation 标明类型，自动发现回归使用单聊资源验证反向隔离；这不是共享算法豁免，也不会关闭旧 HTTP 的单聊限制。
