## 范围与交付

M2 建立带 Persona 身份的群聊内容、候选所属的知情记录、个人历史读取和一次角色生成。在隔离原型中能够保存并展示一条有明确归属的发言；同一内部执行入口允许 M3 串行调用，实现 A → B → A。

指定发言者和知情集合只由内部编排器或测试夹具提供，不加入用户界面或公开请求。M2 不实现导演判断、整轮重生成与切换、恢复续接、持续记忆和角色间关系。它们仍分别属于 M3、M4、M5，不能因本原型省略首版需求。

M2 默认只允许一个未完成或待确认轮次；普通用户发送继续关闭。跨轮确认由 M4 实现，M2 测试可直接构造已确认历史，但内部生成入口不能假装已经具备确认能力。最小展示通过只读历史接入现有群聊详情，生成使用独立临时数据的测试入口，不提供手动选角色按钮。

## 数据方案

群聊内容使用独立表，不把各成员发言塞进 ChatMessage.parent_id 的互斥候选结构。这样旧单聊消息、音频和记忆来源外键保持原义；代价是 M5 要为群聊事实建立明确的证据引用，不能直接把群聊内容 ID 当作 ChatMessage ID。

下面是拟定结构，具体 ORM 命名随实现统一。所有群聊写入集中在领域服务，跨表归属同时校验；能用组合唯一键和外键表达的约束应下推数据库，不能只依赖路由。

| 表 | 主要字段与约束 |
| --- | --- |
| group_rounds | id、session_id、round_index、user_content、selected_candidate_id、confirmed_at、created_at；UNIQUE(session_id, round_index)，用户原文只保存一次 |
| group_round_candidates | id、round_id、version、status、revision、error_code；UNIQUE(round_id, version)；selected_candidate_id 必须指向本轮候选 |
| group_content_items | id、candidate_id、sequence、kind、speaker_persona_id、content、emotion_tag、affection_change、role_state_patch、created_at；UNIQUE(candidate_id, sequence)；kind 为 user/utterance |
| group_content_visibility | item_id、recipient_persona_id、decision、policy_version；主键为 (item_id, recipient_persona_id)，decision 为 visible/hidden |

每个候选以 sequence=0 的 user 内容项引用本轮原文，后续 utterance 从 1 顺序增长。user 项不另存可独立修改的正文，speaker_persona_id 为空；utterance 必须归属于同群成员。用户输入的知情范围也属于候选，M4 重生成时可以形成另一套判定，不能把它挂在 Round 上作为全候选共享权限。

每个已完成内容项为所有固定成员写入显式知情结果，作者自身强制 visible；缺行一律不可见，并报告数据不完整。导演审计理由和模型 reasoning 不进入内容正文或个人历史。程序不得用角色名、昵称或 slot 代替 Persona ID，重名角色仍有不同身份。

M2 只建立 version=1，状态采用 generating、awaiting_confirmation、failed；confirmed_at 预留给 M4。generating 到终态必须由程序写入，不能从最后一条 assistant 推断。候选 revision 每次持久化推进时递增；同一会话不能同时存在两个正在执行或待确认的新轮次。M4 扩展状态转换时保留这些 ID 和归属，不重建候选身份。

新增迁移接在当前实际 Alembic head 后，不改已有 revision。新表通过 Session → Round → Candidate → Item → Visibility 级联删除，Persona 的成员引用需要防止跨群和悬空；所选候选的循环引用采用明确的建表/删除顺序，不以关闭普通业务外键规避。降级遇到非空群聊轮次即拒绝丢弃。整群删除回归必须增加新表清理、外键完整性和 Outbox 失败整体回滚。

## 知情与历史读取

M2 的基本粒度是一条完整内容项，只支持全文可见或全文隐藏。混合公开台词与私密心理的项不能向旁听者开放全文；M2 原型采用保守隐藏，不通过自动摘要或删词制造未经验证的可见版本。M3 设计必须决定是否拆分可见单元，并用真实场景验收这种粒度是否足够；本稿不声称全文粒度已解决所有场景。

知情不等于发言。B 旁听但没有发言，仍保存 B 的 visible 行，以后能读到该项；B 不知情则不保存任何由该内容派生的个人摘要。后来 A 公开转述秘密时，B 只获得转述这一新内容项，旧秘密项继续隐藏。

个人读取入口显式接收 session_id、persona_id、candidate_id 和 before_sequence，不允许传一个会话后取首成员。顺序规则如下：

1. 校验目标是 group、Persona 属于本群、候选属于本轮；只读查询不授予模型执行权，生成编排还须持有会话锁并核对候选版本。
2. 读取早于当前轮次的已确认轮次，各轮仅取所选且成功完成的候选。
3. 读取当前指定候选内 sequence < before_sequence 的已落库内容；不包含其他候选、未来内容、未保存分块或失败结果。
4. 对上述集合按 recipient_persona_id 和 visible 过滤，再按 (round_index, sequence) 排序并应用历史预算。

读取先过滤再限量，不能取全群最后 N 条后再过滤，导致沉默成员丢失可见历史。预算允许省略旧内容，不允许补入不可见内容；省略提示只说明个人历史可能不完整，不泄露隐藏项的数量、作者或摘要。M2 不自动总结被截断历史。

当前用户项只在本次个人可见时进入输入，而且只出现一次；不能在筛选历史后又无条件将 Round.user_content 追加为当前用户消息。当前用户项不可见但存在可见触发内容时，可以回应该触发内容；完全没有可见依据时拒绝调用角色模型，不通过伪造用户台词强行生成。

每项完成后的知情集合不可原地追改。新增判断必须属于新内容或新候选；不允许导演先把秘密发送给角色，再修改权限声称已经隔离。M3 若需要根据生成正文判断接收者，应先持有未公开的暂存结果，判断完成后原子保存正文与完整知情集合，不能先作为公开内容落库。

## 个人 Prompt 与状态

新增 group_context_service 与群聊 Prompt 编译入口，输入为经过过滤的有序内容 DTO。角色卡 DSL、示例、世界书位置和模型参数准备尽量复用现有纯函数；不复制整份单聊编译器，也不直接调用强制 single 的装配服务。

| 输入部分 | 可使用的内容 |
| --- | --- |
| 静态设定 | 当前成员自己的角色卡、卡内风格示例与世界书；不加入其他成员的私人卡片、认知和快照 |
| 共同设定 | 创建时保存的 shared_setting，属于所有成员的共同前提；有值时优先于各卡初始场景，不能把后续秘密写回此字段 |
| 动态背景 | 当前成员自身的基线与候选内有效状态，和明确的身份协议；不传全局场景总结或导演推理 |
| 历史内容 | 仅个人可见项，带真实发言归属；其他角色发言不能冒充本成员的 assistant 历史 |

自身发言使用 assistant 角色，保留现有正文格式；其他成员发言使用带身份和正文的结构化 user 消息，并标明这是已发生的他人发言而非当前用户指令。身份和正文用可转义的结构序列化，不拼接可伪造的 XML 边界。真人用户原文保持独立 user 内容，不混入导演理由或后台资料，不通过宏替换改写用户原文。无需额外补一条虚假的“请回复”用户消息。

世界书触发、递归扫描、检索查询和历史深度计算都只能消费个人可见输入；仅在最终 messages 中移除秘密不够。角色卡提供的示例仍标为风格示例，不当作本群真实历史。PHI 和群聊输出契约继续放最后，共同设定保持动态背景位置。

发言主体由服务端 speaker_persona_id 指定，模型不能改写归属。群聊输出协议只将 emotion、affection_change 和 role_state_patch 作用于当前成员；卡内允许的叙事风格继续保留，但不能借群像卡替其他群成员提交状态或关系。M2 不允许角色输出选择可见接收者，这属于编排判定。

本批不接通 M1 继承记忆检索、事件、图谱或新认知总结；不得调用旧单聊检索补齐这部分能力。M1 已冻结的自身 cognition_state 可作为基线输入，其他成员不能读取。继承事实的读取和持续成长完整交给 M5，并在原型说明中标注尚未接入。

状态从自身 Persona 起点和此前所选候选的自身增量重放，本轮只折叠当前候选中较早的自身增量。M2 将模型增量保存到发言项，不覆盖 Persona 基线；下一次同成员发言能看到自己的变化，其他成员看不到其内部状态 JSON。旁听不自动更新心情或好感；沉默成员成长留给 M5。M4 接管候选恢复，不能依赖改写 Persona 后再反向扣减。

## 单步执行与失败

内部能力拟为 prepare_group_round、build_member_context、generate_group_utterance、complete_group_round；名称不是 HTTP 契约。M2 的确定性测试提供发言者与知情结果，M3 再接导演。角色生成失败必须向编排层返回明确错误，不能复用 generate_reply 的错误正文回退，也不能保存空 reply 或 reasoning 为可见台词。

一次执行按以下阶段完成：

1. 取得既有会话锁，在短事务中检查归属、状态和 revision，建立或校验当前候选，保存本轮用户项及完整知情结果。
2. 从同一读取视图装配不可变个人上下文与调用参数，结束数据库事务后再调用模型；调用期间继续持有会话执行权。
3. 对正文、输出格式和状态增量做校验，由内部判定器补齐本项所有接收者。短写事务内重新校验候选 revision 与生成状态，原子保存发言、增量和知情结果。
4. 编排器明确结束后设为 awaiting_confirmation；异常则设为 failed 并记录非敏感错误码。等待已派发的持久化结束后再释放锁，迟到结果不得写入已关闭候选。

单步函数不自行结束整轮，M2 原型在第一条成功发言后调用 complete；M3 可在同一候选继续追加多条。generation 或知情判断失败均不追加半条发言。已保存前缀保留给用户查看，但 failed 候选不进入后续轮次历史或记忆；不调用单聊 abort 删除整个用户消息。M4 决定正式恢复流程，M2/M3 原型遇到失败即停止，不开放续接或自动重发。

取消、提交结果不确定和进程退出均不得触发第二次模型调用。对遗留 generating 候选只允许标为中断失败，不自动恢复；启动归属与多进程限制在 M2-A 实现时按现有应用生命周期落实，不能单靠进程内锁声称支持多 Worker。独立测试入口必须明确单 Worker，正式恢复由 M4 接管。

## 接口与最小展示

M2-C 已接通只读 GET /group-sessions/{session_id}/rounds，采用 GroupSessionAPIRouter 和现有 X-API-Key；API_TABLE、领域契约和路由快照已同步。本节保留设计边界，正式响应以[群聊 API](../../api/GROUP_SESSIONS.md)为准。

读取返回 round_id、candidate_id、轮次状态与顺序内容项，发言含 speaker_persona_id、角色展示信息和正文；用户原文只返回一次。分页以轮次为单位，单轮内容不拆成丢失身份的分页片段。用户是私有故事的操作者，可查看故事中保存的全部正文和失败前缀；该界面读取不得被角色 Prompt 当成个人历史入口。reasoning、导演审计理由和其他内部字段不进入普通响应。

前端新增独立 GroupRound/GroupContent 类型和领域读取函数，在群聊详情展示发言者与整轮状态，保留 can_generate=false 及无发送框。Mock 只提供明确标为虚构的只读样本，不模拟导演判断正确。组件仍沿用服务器、故事和页内请求版本失效机制，不使用单聊 ChatMessage 或聊天 Store 兼容强转。

M2 使用非流式内部生成；SSE、发言分块终态、整轮终态及只读续接在 M3/M4 再设计。引入流式时继续经 chatStreamProtocol.ts 统一解析，不提前发送单聊 done 伪装整轮完成。

## 验收矩阵

| 场景 | 预期与证据 |
| --- | --- |
| 用户与 A 独处 | B/C 最终 messages、世界书扫描、动态背景及查询输入都不含秘密唯一标记 |
| B 知情但沉默 | 后续 B 的个人历史保留可见项，不因没有自身发言丢失 |
| A → B → A | 最后一次 A 只看到此前获准内容，顺序正确，包含自己首次发言及自身状态变化 |
| 当前用户消息对 B 隐藏 | 不通过最终追加 user、检索 query 或扫描世界书重新注入；无可见依据则不调用模型 |
| A 后来公开转述 | B 可见转述，仍不可见原始秘密全文 |
| 缺失/非法知情记录 | 默认不可见；跨群成员、候选和内容引用拒绝且无部分写入 |
| 隐藏历史占据最近 N 项 | 在完整可见集合上计算窗口，不将可见历史挤出；不暴露隐藏项元信息 |
| 切换测试候选/读取历史 | 仅当前指定候选和此前已确认所选版本，无兄弟候选、失败前缀或未来内容 |
| 同名成员与正文伪造标签 | 身份仍来自服务端 Persona ID；正文不能改变 DTO 归属或知情集合 |
| 私人基线与卡片 | 只读自身认知、状态与角色卡；来源近期聊天、其他成员快照均不进入 Prompt |
| 共同设定与卡片 DSL | 共同场景优先，示例保持示例语义，用户原文独立，PHI/最终契约后置 |
| 模型异常、空回复、非法状态 | 不生成兜底角色台词，不追加半成品；状态失败可检查，Persona 基线不被污染 |
| 取消、知情判断失败、提交失败 | 前缀与状态按事务结果一致，锁最终释放，迟到完成不追加或重复调用 |
| 整群删除与迁移回退 | 新表全部级联，来源单聊与快照规则不变，非空轮次拒绝降级 |
