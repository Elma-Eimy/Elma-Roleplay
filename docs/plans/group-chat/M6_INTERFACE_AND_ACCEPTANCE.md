## 页面与状态边界

详情首先展示故事身份与当前采用内容，成员来源和入群状态按需展开。发言按成员 Persona 匹配头像，正文保留原有顺序与换行；头像缺失使用通用组件的回退，不用姓名匹配身份。当前页继续沿用最近轮次在前的分页方式，不在本批引入自动滚动或流式聊天。

候选预览保持显式的“仅预览，未采用”标记。预览状态绑定候选，不能覆盖成员入群起点。后续当前状态面板应绑定服务端返回的群版本和采用候选；查询期间发生选择、撤回、确认或换服务器时，旧响应失效。不能通过主动读取隐藏知情记录或内部导演审计拼出产品状态。

发送、重生成、采用、续接与撤回继续由现有 composable 执行，按钮权限继续使用服务端 capabilities 和现有失效检查。未知提交只用原 UUID 查询，不能因界面刷新或拆组件再次提交。删除仍需明确确认，失败与取消沿用原有反馈和锁释放规则。

三端使用 uni-app 组件和条件编译，不把浏览器 DOM 或专用 CSS 交互当作通用能力。复用语义变量、状态反馈与安全区；键盘遮挡、滚动高度和触控目标在真机另行核对。

首版仍不提供群聊创建分支、语音、手动调度发言或主动打断。保密、沉默记忆、不同来源人格、整轮一致性与持续成长保持需求基线的要求，不能借界面简化移除。

## 联合验收与保留缺口

M6-D 复用需求基线中的验收场景，分别核对操作者界面、实际角色输入、已确认个人记忆和候选版本。状态一致性不能仅靠截图证明，秘密隔离也不能仅看角色是否在输出中说出秘密。

## M6-B 当前状态与成长面板

2026-11-07：复用候选 GET，新增独立的当前采用状态读取与只展示数据的 `GroupMemberStates.vue`。当前采用、其他候选预览与成员起点分别保存；后端状态继续使用已确认所选历史和目标候选的已保存发言重放，认知起点与群内新认识分开显示。

候选响应增加可选兼容字段 `cognition_state` 和 `insights`，认识只返回种类、正文及关系目标。成员归属、已确认所选轮次与候选成长上界沿用 `member_insights`，不新增任务、不查询模型、不读取来源单聊。Mock 继续明确拒绝候选查询，旧服务器缺字段时不伪造空的成长结果。

前端 GET 只有在返回群版本、最新采用轮次、候选、候选 revision 与状态绑定均吻合时显示。采用/确认版本变化、开始处理请求、离页或换服务器都使旧数据和在途读取失效。查看其他候选保持当前面板不变；只读失败可重试，后台进度不靠重复 POST 恢复。

新增后端状态查询专项 3 项覆盖只读重放、成员与兄弟候选隔离、继承认知、关系归属、成长上界及不暴露证据引文。前端专项增加三端独立读取、版本变更、迟到请求、服务器 A→B→A、错误重试与提交时失效检查。
