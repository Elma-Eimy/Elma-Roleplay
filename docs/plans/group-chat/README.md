## 当前接续点

截至 2026-11-07，M1–M5 代码已接通，正式详情页支持发送、整轮候选操作和恢复；[M6 完整界面与联合验收](M6_INTERFACE_AND_ACCEPTANCE.md) 已接入 A 批阅读结构和 B 批当前状态、个人认识与关系面板。M1–M5 继续标为待验收，构建成功和有限真实样本均不代表全面完成。

已增加当前步骤的有界格式重试、确认后的独立断言提纯与局部记忆更正。十二轮连续实聊暴露过假亲历、时间漂移和混合更正漏记；后续局部更正在固定样本完成真实复验，仍有未匹配更正片段，不能据此认定任意更正稳定。生成前的亲历依据与剧情时间审查尚未实现。证据及最终源码验证边界统一见 [验收索引](../../testing/group-chat/README.md)。

接续时先检查以下未完成项，再读取相关模块设计和实际代码：

- 扩大独立断言、局部更正和来源权限的留出样本，保留未匹配与失败证据。
- 设计并验证生成前的亲历依据与剧情时间审查，不以记忆更正替代防编造验收。
- 开展 App / 微信小程序真机流程，核对生成、恢复和阅读体验。
- 按 M6 分批计划继续设计立绘关联，并联合检查状态、成长、恢复与三端体验。

## 开发顺序与提前约束

以下保留模块拆分时的依赖与约束，用于理解设计取舍。实际下一步以本页的 [当前接续点](#当前接续点) 为准。

默认顺序为 M1 → M2 → M3 → M4 → M5 → M6。先设计 M1，但同时检查 M4、M5 对数据的要求：消息所属成员、轮次与候选版本、知情记录、各成员继承边界和状态恢复依据必须能够表达，避免后面反复迁移。提前检查契约不意味着提前实现全部功能。

M1 完成最小创建和读取入口，M2 能展示一条带明确角色身份的发言，M3 能观察完整互动。指定角色生成仅为 M2 的内部验证能力，不增加用户手动调度需求。

优先用 M2–M3 的小型原型验证秘密隔离、旁听沉默和 A → B → A。质量不达标时先调整核心机制，不急于铺开全部界面。真实模型验证遵守独立配置与数据要求，模拟调度通过不能宣称模型判断准确。

M5 持续形成群聊长期记忆是正式首版要求，不是可删减的附加项。M4 完成前的演示版不得宣称支持可靠的候选切换与恢复。

## 专项文档组织

现有目录分类继续适用，不把尚未实现的设计放入 `docs/architecture/` 冒充当前架构。在本目录按需新增模块设计；没有开始设计的模块不先建立空文档。

M1–M6 专项设计见上表。M6 中新增状态读取与立绘关联在对应批次实施前确定契约。

| 文档位置 | 唯一维护内容 |
| --- | --- |
| 上级总规划 | 目标体验、已确认范围、业务约束及总体设计方向 |
| 本实施计划 | 模块状态、依赖、当前任务、阻塞与交付链接 |
| 本目录的模块设计 | 阶段数据/API/状态机方案、取舍与实施批次；其中状态仅反映设计或交付当时 |
| 现有 features、architecture、api 与 changelog | 实现后的当前行为、模块职责、接口契约和历史摘要 |

模块设计引用总需求，不复制全部需求正文。新增模块设计在本页链接；文档总导航只保留群聊主要入口；实现后将稳定契约同步到对应正式文档，规划中保留未完成事项和必要决策背景。

## 每批交付与接续

每批遵循“读取当前状态 → 设计或实现一个明确范围 → 执行对应检查 → 更新记录”。共享基础设施、迁移和跨端改动的验证范围遵循根协作约定，不因模块拆小而省略必要检查。

批次记录写入对应模块设计、验收报告或 [交接历史](HISTORY.md)，并注明日期与版本；至少包含变更范围、涉及文件或提交、实际检查与结果、剩余问题及下一步。完成状态必须附可核对的证据；失败和未执行的检查如实写明。真实模型与真机验收单独列出，不将测试日志中的敏感内容或真实个人数据写入仓库。

新聊天接续时先读总规划与本页，再读当前模块设计和相关实现。无需从聊天历史重新推断需求，也不依赖另一个泛化项目状态文档来判断群聊是否完成。
