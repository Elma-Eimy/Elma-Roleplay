# 当前角色状态

聊天侧栏的「当前状态」展示场景，以及按人物名称区分的姿势、衣着和位置。心情继续沿用现有字段；本功能不改写角色卡，也不把状态自动写成长期记忆。

## 自动维护与手动校正

- 同一次聊天生成在正文及 `status` 后按需附加 `state_update` JSON 增量，不增加额外模型调用。明确发生变化或首次明确描述时必须返回对应增量，全部未变化时可省略整个更新；程序始终沿用未返回字段的原值，不因缺失而重置状态。
- 场景和衣着可以长期保持不变。计划、假设、未完成的动作不能当作已经发生；未知信息不为填表而编造。人物名称沿用已有名称，最多维护 8 名受控人物。
- 提示词把当前状态（包括手动校正）作为可信度高于召回旧记忆、旧场景和旧认知的本轮起点。当前用户输入或本轮已发生的新动作可以改变它；状态不是永久锁定的角色设定。
- 用户可编辑场景和人物字段、添加人物或清除其状态。空字段表示未知；手动清空场景后不会回退为初始场景。编辑期间暂停自动刷新以保留草稿，保存失败继续保留草稿，可取消后重新加载。
- 生成期间不允许手动保存。保存携带版本摘要，剧情有效消息边界或状态已经变化时返回冲突，不用旧表单覆盖当前状态。离开页面、切换故事或服务器后，迟到响应不会更新新上下文。

程序校验允许字段、JSON 形状、角色数量和文本长度；LLM 更新不接受空值或清空操作，无效的整个状态增量会被忽略，正文仍可落库。校验不等于能证明剧情语义准确，用户仍可纠正漏更、误判或人物名称混淆。

## 剧情版本与持久化

SQLite 的 `SessionPersona.role_state_base` 保存分支起点之前的独立状态快照；`ChatMessage.role_state_patch` 保存模型增量，`role_state_manual` 保存该消息之后的人工校正。读取时仅重放本会话的有效消息，不从检索索引或祖先未来状态恢复。

重新生成使用本轮用户消息及其之前的状态，不把旧候选的结果当作起点。切换候选会重放选中版本；删除消息会去掉其增量及校正。手动编辑助手正文时，移除由旧正文推导的模型增量，保留独立的人工校正。之后的状态仍按剩余有效增量重放，不自动重新调用模型推断。

分支按所选消息之前的边界生成独立基线，再复制该消息的增量与校正；可以从非激活候选创建分支。父线未来内容或后续手改不会回写子线；删除分支起步消息也能回到它之前的基线。

迁移 `a6b7c8d9e0f1` 以可空列升级旧库，旧消息保持不变，不回溯调用模型补填历史状态。启动会沿用现有 Alembic 机制升级；降级只移除新增状态列。

接口与字段限制见 [HTTP API](../API_TABLE.md)。
