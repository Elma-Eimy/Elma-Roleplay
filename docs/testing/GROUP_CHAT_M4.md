### 已发现的语义缺陷

### 叙事指令暴露的两种不稳定

## 2026-11-06 轻量回合计划第一版

在前述信息投影修复上增加结构化回合计划，未引入多智能体框架依赖或完整世界模拟。流程借鉴 [Concordia 的观察、调度与结果裁定拆分](https://github.com/google-deepmind/concordia/blob/main/concordia/environment/README.md)；落地仍使用现有导演、SQLite、候选审计与检查点。

### 当前行为与兼容

- 用户初判为每个原文片段标记 fact、speech、request、private 或 uncertain。recipients 继续表示剧情感知，request_to 独立表示可读取推进请求的成员；请求不会因此被写成已发生事实。private 不允许感知授予或请求对象；混合内容仍需分段，含义不明保留 uncertain，不由代码补全事实。语义分类本身仍可能判断错误。
- 导演选人同时选择 basis，引用当前请求或个人可见历史。请求对象、同候选/已确认所选历史及窗口边界由服务端校验，调度保存与角色输入装配分别复核。该成员已提交过回应的请求不再作为未回应请求提供，但这不表示请求中的行动已经完成；后续仍可依据新发言推进。来源窗口裁剪同时移除引用选项，不向角色暴露全局内容编号。
- 发言后判复用原有一次调用，增加 review=ok、agency_conflict 或 unsupported_history。只拦截明确的主体控制与无依据历史，不逐句审查合理创作；引用、转述和用户明确授权的范围分别判断。不确定时不强行否决。拒绝不提交正文、状态或未通过的知情单元，保留原依据和检查点供显式续接；第一版没有自动纠正生成，也没有增加每轮调用上限。
- 请求元数据、依据和已接受审查结果存入现有审计 JSON，策略冻结在调用快照可选 turn_policy，无表结构或迁移链变化。旧快照缺字段按旧策略恢复。app.group_turn_planning 默认 true；llm.group_json_mode 默认 false，只在实际服务支持时启用 json_object，不能代替必填字段校验。普通单聊不变，显式 v1 内部执行保留 XML 角色输出。两个选项均为服务器启动配置，既有候选不随配置切换策略。

可读取的推进请求也参与世界书匹配，仅扫描实际授权片段；世界书不扫描旁人私密内容或内部身份包装。前端 error_code 已是字符串，仍按现有失败与续接交互处理；Mock 不模拟新语义，未改前端实现。
