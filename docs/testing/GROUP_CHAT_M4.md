## 2026-11-06 隔离 H5

复制白名单源码和构建产物到临时目录，生成 `.invalid` 模型地址的测试配置，不复制开发配置、凭据或数据库。用 `test_group_operations_routes.py` 的 TestClient、临时 SQLite、后台运行权和模型替身提供真实路由；本机代理仅监听 `127.0.0.1:18767`。临时 H5 副本的默认请求地址指向该代理，未改生产连接配置或 M3 只读预览保护。

两个测试成员都命名为“无名”，实际发言继续显示成员编号。通过浏览器操作完成以下场景：

| 操作 | 已观察结果 |
| --- | --- |
| 首轮发送 | 用户原文保存一次，后台结束后显示 REPLY_0，输入清空，成员起点仍为 0 |
| 整轮重生成，注入角色调用失败 | 当前采用仍为旧候选，失败候选单独显示“未完成”，预览不会切换选择 |
| 显式继续失败候选 | 确认对话框提示沿用参数与可能再次调用；恢复成功后采用候选 2，预览好感为 2，起点仍为 0 |
| 切回候选 1 | 当前采用正文恢复 REPLY_0，候选 2 改为“仅预览，未采用” |
| 发送第二轮 | 第一轮标为已确认，采用的是切回后的 REPLY_0；第二轮独立生成 |
| 撤回第二轮并刷新页面 | 第二轮不再出现在普通历史，第一轮保持已确认；没有自动重发旧消息 |

代理记录共 6 次对应写操作；进展与补刷均通过 GET。页面滚动检查了成员卡、已确认正文、输入区与底部操作，没有运行整群删除。所有模型输出都是替身数据，故障通过测试夹具注入，不代表真实模型恢复质量或真实费用。
