## 2026-11-07 修复范围

本批处理两个已知缺口：把听说或旧自述当成本人亲历，以及整句请求分类吞掉夹带的事实更正。剧情时间审查不在本批范围。

新群聊候选冻结 `experience_guard=true`。生成草稿后，独立的 `role_experience_review` 只读取本人可见历史、有效记忆片段、待执行请求与该草稿，不能读取角色卡示例、其他成员私有记忆或导演全局资料。审查器列出肯定亲历表述及来源，程序核对输出原文、引用、来源种类、已知来源与异议状态。说法可以证明听到该说法，不能证明本人亲眼见过所述事件；请求和计划不能证明已经执行。

缺少依据时，角色最多按冻结的输出尝试次数重写；未通过的草稿不会进入导演知情判定，也不保存正文、状态或知情行。审查格式无效有单独的有界重试，耗尽后停止，不通过反复改判放行。每次调用使用原持久计数与期限，启用审查的额度为 `output_attempts × (4K+1)`。旧候选缺字段时保持原策略，重生成采用新策略，不追溯改写历史发言。

生产提纯在首轮分类后重新审查全部本人可见原文，包含初次标成请求的内容。复核仍需完整逐字分段，不能静默丢弃已识别更正。未匹配更正也必须保留来源卡和诊断；查找旧事实最多 12 条，发言召回仍最多 3 条，既有成员、确认和候选上界不变。

## 原始失败与验证限制

最初尝试复用导演判定，回归发现会把成员私有记忆带入导演输入；该方案已移除，改为个人资料隔离的独立审查。原始日志保留。其后回归发现直接生产策略的旧调用次数断言少算一次审查，更新断言并核对审查恰好调用一次。日志保存在 Git 忽略的 `docs/local/previews/group-chat/`，本报告不假设其他机器有这些文件。

本批未调用真实模型或 Embedding，也未读写开发数据库；未重新构建前端或操作真机。独立审查仍依赖模型识别并列全亲历表述，引用有效不等于语义一定正确；两次分类也不能保证任意表达都不漏更正。下一次真实验证须按新批次留出样本，检查否定、转述、条件、原说话人撤回、他人异议及持续多轮效果，不能沿用此前真实批次的通过结论。

## 2026-11-07 真实 API 有限复验

随后以当前源码的冻结副本和全新虚构库执行批次 `2026-11-07-source-correction-live-00bcd71a`，运行中未修改应用源码。使用已配置的 `deepseek-v4-flash` 聊天/记忆模型与 `doubao-embedding-vision-251215`，JSON 模式 false，完整群聊历史窗口 10。定向审查温度 0.2、输出上限 2048；完整群聊使用实际冻结参数，单次期限 60 秒，同步定向审查与记忆调用设 90 秒上限，SDK 不自动重试。

一次提纯将分段限定的 statement 持续写成 narration，三次校验后被拒绝并退避；第 2 次任务执行恢复，最终待提纯任务为 0。没有降低来源类型校验。完整群聊中有两个 `correction_unmatched`：由于此前并未提供对应错误维修记忆，没有旧目标可以替换，但更正正文和条件均已保存，不能将其算作成功关联旧事实。

聊天、审查与提纯共 63 次调用，Embedding 文本请求 19 次；输入 57,633、输出 7,913，合计 65,546 tokens。物理卡 19 张，其中 2 张是预置旧卡；直接同步 18 张并执行 1 次真实语义查询。Outbox 的 19 条任务仍排队，因为本批没有启动该 Worker，不能把“待提纯为 0”写成“全部后台无积压”。本地 SQLite、Chroma、源码散列、工作区补丁、逐次输入输出、失败和对话均按批次归档，配置凭据值扫描未发现泄露。

两组更正的旧卡及前置对白是预置样本，实际取证、分段、提取、提交与有效视图使用生产服务。三轮群聊的末轮回答仍有短历史可用，不能单凭它证明长期召回；也没有自然触发一次亲历重写，定向拒绝不等于已验证所有生成场景。没有操作真实用户库或 App/微信真机，不把有限样本结论扩大为普遍稳定性。完整对话与复核的本机入口仍为 `docs/local/group-chat-tests/README.md` 和 `index.json`。
