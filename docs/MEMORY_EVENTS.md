# 进行中事件与长期记忆写入

自动提纯仍按已确认消息数量触发。触发后，稳定事实、偏好、明确承诺和重要关系转折可以直接写入；尚在展开的同一次事件先进入 SQLite 的 `memory_event_buffers`。后续提取能看到事件摘要，补充原事件，而不必每批新增一张长期卡。

## 提取与收尾

模型在事件卡上返回 `event_status` 和 `buffer_id`。`ongoing` 表示继续缓冲，`complete` 表示本段事件收尾；更新已有事件时引用输入中的整数 ID，新事件使用 `null`。旧输出缺少这些字段时按完整卡兼容，不强迫旧模型遵守新结构。

例如，海边约会、下雨转到咖啡馆、谈心后结束约会，分别跨越三次提取。前两次更新同一缓冲，最后一次写成包含起因、转场和结果的事件卡。明确的“明年再来海边”承诺可以单独按 `planned` 保存，事件收尾不会将计划改成已经发生。

事件缓冲有固定边界，当前没有单独的设置界面：

| 边界 | 行为 |
| --- | --- |
| 最多 3 个进行中事件 | 超出时收尾最早创建的缓冲 |
| 累计 3 个成功处理批次 | 收尾该事件；模型未提及时也累计批次 |
| 来源达到 60 条消息 | 收尾该事件；加入当前完整批次后检查，不截断来源指纹 |
| 场景结束、明显转场或话题切换 | 模型返回 `complete`，写入完整事件 |
| 手动提纯 | 主动收尾当前有效缓冲；没有新消息时直接处理已保存摘要 |

“收尾”表示将目前有依据的摘要转为长期记忆，不表示故事中的计划已兑现或客观事件一定结束。长期写入仍经过专用候选检索与 `same/replace/coexist` 判断，复用不新增卡，替代保留旧版本。创建分支时的收尾直接保存已有摘要，不额外调用模型。

缓冲最多注入三个、每个约 500 字符以内的事件摘要，放在聊天 Prompt 的动态背景 `<ongoing_events>` 中。它们不写入向量索引，也不计入长期记忆列表或统计。提取指针推进后，聊天仍可延续这些场景；重启不会丢失缓冲。

在提取规范化阶段，同批落在同一事件消息区间内、时间状态相容的低权重瞬时情绪（`emotion`）碎片会自动并入宿主事件卡，并同步重映射图谱依据下标；同批指向同一有效 `buffer_id` 且时间相容的重复更新也会预先归并。

片段只在拼接正文能完整容纳时吸收。事件拼接超过 500 字符时提前收尾宿主，将后续片段作为独立完整卡保存；情绪拼接超长则保留独立情绪卡。此处优先保留已有信息，不通过截断合并结果减少卡数。

## 来源、事务与分支

每个缓冲属于本故事的 Persona，保存摘要、故事内时间状态、消息指纹和图谱候选。更新只能引用当前有效缓冲；不接受其他故事或已经移除的 ID。跨批次更新允许时间状态从 `unknown` 收敛为明确状态（如 `historical`/`current`）或补充此前缺省的 `temporal_note`，但拒绝与 `planned` 跨界或互斥时间状态/说明的混写。程序合并旧来源和本批支持消息，保留跨批次的完整来源指纹。

事件本身的来源被修改、删除或切换为 inactive 后，该缓冲停止注入和发布，下次处理时清理。图谱辅助来源独立校验，辅助消息失效只移除相应图谱候选，保留自身来源仍有效的事件。不会用已经失效的摘要生成新记忆，也不会自动重新提取此前已越过接收指针的旧消息。

主提取调用在事务外完成。模型输出规范化后，候选与接收指针在短事务中原子保存到 `memory_extraction_jobs`，接收指针不再代表长期卡已提交。图谱引用的候选组成依赖组件；同批事件共享容量决策，因此归入同一组件，其他无依赖事实可独立提交。

每个组件先读取快照，在纯内存中规划事件更新；向量查询和关系模型调用期间没有数据库事务。完成判断后，在短写事务中复核任务租约、消息指纹、旧卡与缓冲版本，将事件、长期卡、图谱、Outbox 和任务完成状态一起提交。单个组件失败不会回滚其他已提交组件，任务保留候选等待重试；成功任务清空候选正文，仅保留状态与计数。

独立记忆 Worker 每五秒检查到期任务，使用退避与可恢复租约；同故事部分唯一索引保证同时最多一个处理任务，token 防止过期处理者提交。它与向量 Outbox 分开运行，服务关闭等待正在执行的线程释放自己的数据库会话。主提取失败也会登记捕获重试任务；恢复后无需新消息即可继续接收积压。此 Worker 不按闲置时间主动结束事件，停止聊天后可以手动提纯收尾。

HTTP 手动提纯和回合维护只可靠登记捕获请求，不等待模型；手动接口返回当前队列状态，新增数量保留字段为零，完成结果通过记忆列表与日志查看。离线 Mock 明确不执行提纯，不虚报生成数量。

聊天动态背景另提供最多八张有效待处理候选，标明可能重复、尚未整理，避免接收指针推进后立即失去上下文。关系模型接收完整时间语义与来源边界；正文相同但时间更明确时保存新版本，补处理较早消息不得覆盖较晚来源支持的当前卡。

分叉时只收尾来源完整落在 `fork_message_id` 之前或等于它的有效父故事缓冲，让子故事通过现有长期记忆视图继承。跨越分叉点的摘要包含未来信息，既不收尾，也不复制给子故事。分叉和收尾共用创建会话事务；分叉失败一并回滚。尚未结束的父故事事件可能因此提前形成一张长期卡，后续进展再走正常写入查重。

图谱候选随事件暂存，事件进入长期记忆后才发布。跨批次更新以模型本次返回的图谱为准，不保留可能已经过时的旧关系；未更新而被强制收尾时使用已保存的候选。当图谱项同时引用进行中事件与本批已落库的长期卡时，缓冲会携带已落库卡的证据绑定（`_extra_bindings`）与对应消息指纹，待事件收尾时校验全部关联卡仍然有效后共同发布；若多卡依据中包含其他尚未落库的缓冲项则本批不写入，绝不把多卡依据擅自降为单卡。

## 日志与验证

容量收尾时，本批释放的图谱候选与仍在缓冲的候选都在长期卡写入后解析跨卡依赖；未落库依据不会被忽略后按单卡发布。混合字符串、对象或布尔值的非法图谱下标安全拒绝，合法记忆与图谱项可继续提交。

`[MEMORY EXTRACTION] events` 记录本次缓冲更新数、收尾数和剩余进行中事件数；写入结果仍使用 `new/replaced/reused/written`。`buffered` 包括更新已有缓冲，`flushed` 表示已有或容量超出的缓冲进入收尾流程，最终是否新增还取决于写入去重。日志不打印事件正文或模型原文。

表结构由 `a2b3c4d5e6f7_add_memory_event_buffers.py` 迁移建立。回退该迁移会移除待处理事件表，已经写入的长期记忆保留；旧库升级不会改写现有记忆。

候选任务由后续迁移 `a3b4c5d6e7f8_add_memory_extraction_jobs.py` 建立。回退候选任务迁移时，仅将仍有未完成候选的故事接收指针退到最早待处理来源之前，让旧代码可以重新提取；已提交的长期卡保留。

离线回归见 `app-backend/tests/memory/test_memory_event_buffer.py`，覆盖跨批次合成、时间状态收敛、瞬时伴随情绪吸附、跨卡图谱绑定、直接写入的事实与承诺、缓冲上限、重启与手动收尾、图谱事务、来源失效、并发版本及分叉隔离。迁移回归见 `app-backend/tests/infrastructure/test_memory_event_buffer_migration.py`。这些测试不调用真实模型；场景识别和摘要保真仍需实际对话验收。
