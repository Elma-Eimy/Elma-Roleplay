## 2026-07-31

### 修复：回复标签解析与流式落库

- 将流式和非流式回复统一到 `services.parse.extract_xml_block` 进行最终解析。
- 容错处理缺失、重复嵌套和残缺的 `reply` 标签，并兼容模型偶发输出的
  `replay` 拼写。
- SSE 流式输出保留尾部缓冲，避免把尚未接收完整的 XML 标签发送给前端。
- 流结束后始终以完整模型原文的规范化结果保存消息，不再使用流式临时
  缓冲作为数据库正文。
- 数据库继续只保存纯回复正文；重新组装历史 Prompt 时才包装
  `<reply>/<status>`。

### 修复：候选回复的记忆提纯时机

- 采用“进入下一轮即确认上一轮”的规则。
- 自动触发计数和实际提纯批次仅包含：

  ```text
  last_summarized_msg_id < message.id < 最新 active 用户消息 ID
  且 message.is_active = true
  ```

- 当前用户消息及其候选回复不会提前进入长期记忆。用户发送下一条消息后，
  上一轮最终 active 候选才获得提纯资格。
- 短期历史交接仍统计并保留当前未确认回合，延后一轮不会造成上下文空档。
- 已经进入下一轮的候选组被冻结；如需改变更早的剧情，应创建会话分支。
- 本次修改不新增数据表或字段，不需要数据库迁移。

### 测试

- 新增回复标签容错解析测试，覆盖嵌套标签、残缺闭标签、缺失开标签、
  `reply/replay` 兼容和 status 属性顺序。
- 新增候选确认边界测试，验证当前候选不计入提纯、下一轮只确认最终 active
