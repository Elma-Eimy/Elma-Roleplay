# 群聊功能与业务规则

2026-11-11 本地返工改为普通共同群聊：新候选中所有成员读取本轮共同正文，角色复用单聊 XML 与提示词组装，导演只决定下一位发言者或结束。裁决与私密分段冻结，旧角色 JSON 生成、格式转换和发言审查执行已删除；旧候选保留原权限，不静默公开旧内容。生成完整回复后逐条保存，后续失败保留前缀。群聊资料的成员页可逐人查看当前提示词组装，复用单聊预览组件；尚无轮次时不可预览。以下旧裁决机制仅作兼容说明，真实模型质量与移动端逐条展示仍需验证。

[文档导航](../README.md) · [群聊管理 API](../api/GROUP_SESSIONS.md) · [实施进度](../plans/group-chat/README.md)

共同群聊的导演现在逐次选择“谁发言、主要回应哪条消息、是否继续”，可以安排 A→B→A、同一成员连续发言，或让 B 回应 A 较早的一条消息。导演看到本轮各成员已完成的次数，角色收到明确的回应原文及本人本轮发言序号；用户要求分次说时，每次只完成当前一步。没有需要角色承接的内容时结束等待用户，不强制每人轮流发言。角色仍使用自己的角色卡和单聊 XML；次数与承接自然度需结合实际场景验证，执行预算继续有效。

目前可以创建、查看和删除群聊，为固定成员保存独立的人格起点。详情页支持发送、整轮重生成、候选预览与切换、显式续接和撤回；角色由导演串行选择，没有手动选人或主动打断按钮。确认上一轮后，后台为知情成员提取个人记忆卡，沉默的旁听者也可形成记忆。

## 创建和查看

故事首页的“群聊故事”进入独立列表，列表支持刷新和分页，不混入单聊故事。点击“新建”后填写群聊标题、用户昵称与共同设定，选择 2–3 名不同的角色。

每名成员可从原卡开始，或选择该角色的一条单聊作为来源。界面明确提示“导入当前已保存状态与记忆”：导入的是创建时已经落库的状态和有效记忆，不是任意历史时点的还原。具体记忆边界与服务端事务规则见 API 契约。

原卡成员默认采用角色卡默认开场，也可选择备用开场，预览并编辑，或清空跳过。开场对全体成员可见，创建前应检查其中的角色、场景与私密描写；保存后按成员顺序冻结显示，不随角色卡修改。导入培养人格的成员不插入开场，两种来源可以混用。预置开场不触发自动接话，始终由用户发送第一条主动消息启动生成。旧群聊不自动补开场。

成员与共同设定创建后固定，当前不提供编辑或逐个增删成员。创建成功进入详情，展示成员、来源模式、导入卡数量、保存时间、好感度、心情、认知与场景。来源单聊之后继续聊天、修改记忆或被删除，不改变已经冻结的群聊起点。

详情复用单聊顶栏、固定底部输入栏与气泡样式，正文支持相同的 Markdown 排版。右上角打开资料侧面板，设定及成员起点按需展开，并明确标记为入群时固定资料。发言按成员身份配头像，采用内容与候选预览保留各自标记。删除入口收在资料面板的群聊管理中，仍需二次确认。

群聊沿用单聊的字号、行距、小说/气泡排版与色调。默认显示角色立绘背景，跟随当前采用内容最后发言的成员，无发言时使用首位成员；可在外观页固定查看一位成员或切换纯净背景。立绘不可用时回退头像，候选预览不改变背景；顶部相机按钮可进入立绘独占模式。已有开场时不再显示空对话提示卡。

最新轮次还没有角色发言时，继续跟随此前最后发言的成员；仅在整个已加载历史中没有角色发言时回退首位成员。翻页失败或页面失效时不恢复旧锚点，已排队的定位回调也检查原页面代际。

抽屉顶部、成员列表和起点资料中的角色头像可打开对应角色详情。跳转使用页面栈，返回保留当前群聊与未发送草稿；打开失败时保留抽屉并提示重试。

输入栏上方和抽屉外观页均可打开与单聊共用的模型面板，模型、思考开关与强度按服务器和故事在当前设备保存。发送及整轮重新生成等待配置就绪，并冻结点击时的选择；加载失败或等待期间离页不会发出生成请求。继续未完成候选沿用后端已冻结参数，不套用后来选择的模型。

输入区沿用共享键盘适配：App Android 使用 `adjustResize`，iOS App 和微信使用键盘高度占位；H5 根据可见视口被遮挡的高度补位，窗口已缩小时不再重复加占位。键盘打开与输入框获得焦点时分阶段置底，键盘收起恢复底部安全区留白。真机键盘动画与输入法差异需另行验收。

“当前采用的成员状态”按需读取本页当前采用轮次与候选，展示好感、心情、场景及角色状态，另外区分继承的认知起点与群内形成的个人认识、对用户和同伴的看法。成长资料以该候选当时可用的范围为准，后台稍后完成的提纯会在新候选生效。切换、确认、撤回或处理新请求时旧面板失效，需要重新读取；候选预览不会覆盖当前采用状态。读取失败可重试，无采用候选时查看入群起点，旧服务器未提供的资料明确显示不可用。

“成员立绘”支持分别选择各角色的已有素材或使用头像。群内起步选择不改写入群来源，发送和整轮重生成冻结当前采用的全员选择；失败保留旧采用结果，续接使用原快照，切换候选和撤回恢复对应图像。已有轮次时仅允许修改最新未确认采用候选，生成与其他活动任务期间不能修改；已确认轮次保留原选择。候选预览与状态面板展示候选自己的图像，素材删除后回退头像。旧候选缺少新快照时使用入群选择，旧服务器缺字段时仍用头像阅读；没有自动表情、群聊立绘上传或手动发言调度。

离线 Mock 只支持原卡起步，创建页不提供快照导入选项，并说明尚未支持的能力。

## 已保存发言

详情页按时间从上往下展示当前采用的内容，最新消息在底部，可从顶部加载更早轮次并保留阅读位置。上翻阅读时新内容不强制置底，点击最新消息提示可恢复跟随。同一轮内保留用户原文和角色发言顺序，使用成员身份区分同名角色。候选状态显示为处理中、待确认或未完成，已确认轮次单独标注。失败时已提交的前缀仍可查看，只有服务端判定可续接的候选才提供“继续此候选”。

正常结束可显示等待下一步、无可见依据或达到发言上限；旧数据没有停止原因时继续按候选状态展示。失败错误码不作为原文显示，超时与一般失败使用固定提示。内部导演到现有 H5 页面的验证方法见[群聊 M3 联通验收](../testing/group-chat/M3_DIRECTOR.md)，该隔离预览保持只读；正式详情页的发送能力由独立后台接口提供。

角色复用单聊 XML、status 与 state_update 容错解析；截断或空正文明确失败，保留已完成回复。旧 JSON 生成、格式转换与发言审查实现已删除，不再通过额外模型转换或重写正文。思考强度和输出额度沿用配置，不额外提升 token 或强制使用审查参数。

角色卡与世界书示例保留原文，复用单聊示例编译和 XML 格式，自身历史同样使用 XML。

刷新或翻页失败保留原有内容，重试对应页；切故事、切服务器、离页及删除后，迟到响应不能恢复旧内容。该视图面向故事操作者，可以看到故事中的全部正文；角色模型仍只读取自己获准知情的内容。成员面板始终展示起点；候选详情另列好感、心情和角色状态预览，明确标注当前采用或仅预览。

## 推进剧情与候选

导演根据用户原话和本轮已完成次数选择下一位成员及回应消息，或结束等待用户；不再调用请求分类或审查模型纠正导演决定。

发送保留用户原话，默认沿用服务器的生成配置。发送下一条消息的接受事务会确认上一轮当前采用的完整候选；生成失败的轮次不能直接确认。整轮重生成期间保留旧选择，新候选完整成功后才切换；失败候选不提供“采用”操作。

“继续此候选”沿用该候选的原参数和已保存前缀，不重复已提交的发言；未保存成功的步骤可能再次调用模型，界面会在确认时提示。不能续接的旧候选仍可重生成或撤回。撤回只移出最新未确认轮次，更早已确认历史保持不变。

写请求前先把请求 ID 保存在本机，按服务器地址和群聊编号隔离；本机保存失败则不发送。后台执行期间只用 GET 读取进展，关闭页面不会取消后台。返回或重建页面时先找回本机请求或服务端活动任务，再决定可用操作。网络错误、查询 404 或补刷失败均保留待确认状态，允许重新查询，不自动重发 POST。

候选列表支持分页，预览不改变当前采用内容，也不覆盖成员起点。生成、提交或结果待确认时禁用新写操作和删除。旧服务器缺少 current 元数据、离线 Mock 或生成服务不可用时保留阅读能力；服务端仍决定选择、撤回等短事务是否可用。

如果候选查询或翻页发现剧情已被其他页面更新，需先刷新主历史，看到最新采用内容后才能继续操作。删除也会等待历史和本机请求记录读取成功。明确拒绝的请求若本机记录清理失败，可恢复存储后重新查询以清理；不会重发原消息。

## 提交、失败与删除

创建期间禁用重复提交和成员修改，已发请求使用点击时的参数快照。明确的参数、资源或忙碌错误保留草稿，允许修正后手动提交；超时、断连或提交结果不确定时，页面不提供直接重发，应先返回列表确认是否已经创建。

离页、切换服务器或 A→B→A 切服会使旧请求失效。旧响应不能恢复旧表单、覆盖新列表、清除新请求的忙碌状态或触发跳转。详情页切服后不复用同号故事，要求返回新服务器的群聊列表重新选择。来源选择也按成员和请求版本隔离，移除后重新加入的同名角色不会接收旧来源列表。

同一服务器内返回创建页时，被离页中断的来源读取会重新加载对应页，保留已加载的来源和已选故事。重新确认相同来源模式不会清空选择；切换模式时才重置来源。

删除需要确认整个群聊，界面说明来源单聊和角色卡会保留。确认期间阻止重复操作；离页或切换对象后的过期确认不会发出删除请求。已发送的请求可能在服务端完成，前端失效只阻止迟到回写，不撤销服务端事务。

## 验证范围

流程回归覆盖 H5、App Plus 和微信小程序的提交保护及作用域失效。三端构建分别检查编译兼容，H5 使用隔离临时后端和虚构数据走通首页入口、原卡创建、快照导入、详情、删除和列表刷新，并检查移动端及宽屏布局。

没有操作开发数据库或调用真实模型。App Plus、微信小程序的真机交互，以及后续角色互动质量仍需单独验收；构建成功不代表这些场景已经通过。

## 后端内容基础

角色可以根据看见的动作主动搭话。本轮已发言者只列该角色实际可见台词的作者，回应依据保留台词、动作和心理的类型。新候选区分用户要求口头作答、完成动作或任选一种回应。导演在已有的发言后判中核对本次回应与其承接的请求，记录已完成、明确拒绝或仍待回应。只有点头时，要求解释的请求继续保留；用户只要求点头时，同一个动作可以完成请求。待回应允许留到本轮结束。

新候选默认使用轻量回合计划：用户推进请求与角色实际感知分开，未执行的安排不会仅因被读到就成为剧情事实；每次选人附带经服务端验证的承接依据。发言后判同时检查明确的主体控制和无依据历史，失败时保留检查点供显式续接，不自动反复生成。旧候选继续沿用原策略。此机制不保证所有自然语言判断正确，当前证据与轻微叙事推断残留见[群聊 M4 验收](../testing/group-chat/M4_ROUNDS_AND_RECOVERY.md)。

格式无效与语义拒绝分别处理：新候选当前步骤出现非法 JSON 或缺字段时，最多尝试三次（含首次），此前已保存的发言不重复生成。新候选另用独立调用检查本人亲历依据，缺依据的草稿可有界重写，未通过时不保存正文或状态。听说、请求、计划和旧自述不能证明亲眼见过；资料只供本人审查，不扩散到导演或其他成员。通常每次发言增加一次审查调用，所有尝试共享整轮期限与调用额度。超时、网络错误、截断、取消和其他语义拒绝不自动重试。旧候选沿用冻结策略，详见[群聊接口](../api/GROUP_SESSIONS.md)。

用户输入初判先拆开事实、台词与待执行请求，再分别判断知情。记忆提纯对本人可见原文先分类再独立复核，避免整句请求吞掉更正。明确更正优先形成独立事实卡并关联旧片段；找不到目标时也保留更正卡与未匹配诊断，不随意覆盖旧事实。认识与关系仍从正确对象的原话取证。这些语义判断依赖模型，已有有限真实 API 复验，仍需扩大留出样本；具体条件与失败恢复见[专项复核](../testing/group-chat/SOURCE_AND_CORRECTION_CHECKS.md#2026-11-07-真实-api-有限复验)。

v2 个人输入保留获准台词、动作和心理类型，其他成员发言作为带作者的历史资料，用户原话仍独立；当前身份与本轮已见发言者来自个人可见记录。请求、承诺与未来安排不自动视为已执行，导演知情与发言需求分别判断。这些改进不代表模型语义已全部修复，真实调用仍记录到归属、时序及输出格式残留，详见下方验收链接。

M2 已提供内部轮次、整轮候选、个人 Prompt 与单步生成，个人历史先按成员可见性筛选再限量；缺失判定默认隐藏。模型只使用自己的角色卡、认知、起点与状态增量，世界书也只扫描可见输入。个人历史用换行分开原文中不相邻的可见片段，世界书按连续片段匹配关键词和正则。扫描深度只限制历史消息条数；深度为 0 时，仍匹配当前上下文中的本轮可见用户原话和面向该成员的待回应请求。共同设定作为背景，不强行写入限长场景字段；用户原话独立，其他角色发言带服务端身份，不能改写归属。

内部导演已接通知情初判、调度、角色生成、单元后判及终止审计；M4-C 已提供 HTTP 发送、候选操作和恢复查询。隔离回归覆盖单元过滤、串行 A → B → A、失败和取消；真实模型已补有限样本的单元分类、知情、候选操作、最终提交故障恢复及多人交互边界，但发现用户/角色指代与行动归属混淆、简略叙事请求知情判定及发言时序不稳定，详见[群聊 M4 交接](../testing/group-chat/M4_ROUNDS_AND_RECOVERY.md)。新候选从发言成员自己的入群快照和已确认群内新卡里，按可见话题召回最多三张，标明来源和时间状态。若成员亲历了对旧事实的明确修正，后续候选可以只看到修正后的卡。成员还会从自己可见的已确认经历中形成认识，包括对用户或其他具体成员的印象。后台处理完成后，新建候选会在本人发言时带入这些看法。互动质量及 App/微信真机阅读尚未完整验收。

应用强制同一数据库单进程运行，启动时将此前中断的 generating 群聊候选标记失败并保留已保存内容，不自动重试或确认。M4-A–D 已接通内部事务、HTTP 与详情页操作；离线与 H5 联通证据、真实模型及真机待验收项见[群聊 M4 交接](../testing/group-chat/M4_ROUNDS_AND_RECOVERY.md)，契约见群聊 API。

群聊成员面板直接复用单聊抽屉，可切换成员查看好感度进度条、心情、角色状态、认知、立绘和当前 Prompt。好感度表示该角色对用户的数值，进度条只将显示宽度限制在 0–100，实际累计值不由界面截断。向量记忆库复用单聊搜索、分类与分页界面，按成员读取继承与群内已确认记忆；暂不开放群聊记忆的编辑和整理。正文使用同一 ChatBubble，群聊模式隔离单聊候选、朗读和修改动作。
