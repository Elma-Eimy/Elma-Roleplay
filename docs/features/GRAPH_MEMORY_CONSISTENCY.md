# 图谱与长期记忆的一致性

图谱记录实体、别名与关系，向量 RAG 召回语义记忆种子。聊天通过联合检索扩展图谱并回查 SQLite 支持卡，统一来源校验、故事边界、去重与预算后进入 Prompt；当前尚未增加语义重排。

## 提取与来源

- 自动提纯仍只处理由下一轮用户消息确认的 active 对话。同次模型响应输出记忆、实体和关系，SQLite 主数据与向量 Outbox 在同一事务提交。
- 实体和关系可通过 `memory_indices` 引用本次 `memories` 原数组的下标（从 0 开始）。规范化丢弃寒暄或重复卡后，引用仍使用原始下标；引用被丢弃的卡、越界值或不合法类型时，跳过该图谱记录。
- 缺少 `memory_indices` 的旧模型响应，保守依赖本批全部实际保留的记忆；任一依赖失效时，对应记录不再召回。没有有效记忆依据的图谱输出不写入。
- `same` 复用保留卡作为依据，`replace` 使用新卡并沿用记忆的替代链；不另按 `likes` / `dislikes` 等词猜测全局冲突。模型若将互相矛盾的内容判为 `coexist`，仍需纠正或整理记忆，不能声称语义冲突已全部解决。
- 关系判定前排除消息来源已失效的旧卡，允许本批有效证据生成新卡；判定期间若旧卡正文或来源变化，回滚本批并保留提纯指针，等待重试。
- 来源快照包含实际支持消息的 ID、角色与正文指纹，以及支持记忆的 ID 和正文指纹。模型返回后、整批提交前均复核消息，复用/替代前另检查候选记忆是否仍有效；来源被编辑、删除或切换为非 active 时，回滚本批写入，不推进提纯指针。

## 版本与分支

`GraphEntity` 和 `GraphRelation` 增加 `source_start_message_id`、`source_message_id_bound`、`evidence_json`，来源边界为独立整数，不随消息外键删除而丢失。实体额外使用 `is_stub` 区分关系端点的身份桩与有描述的实体定义。

- 图谱更新追加新行，不原地覆盖历史描述；同名实体、同一方向三元组在可见范围中优先使用当前故事、最新来源和最新记录。同一关系的新版本低于重要性阈值时，不会恢复更旧的高权重版本。
- 祖先记录严格限制在对应 `fork_message_id` 之前或边界处；缺少可靠分叉边界时不继承该段图谱。聊天装配另传入当前用户消息 ID，屏蔽本轮之后的当前故事记录。
- 父故事分叉后的新增与更新不进入旧子线，子线记忆替代也不影响父线或兄弟线；多级继承分别检查每段边界。
- 关系端点仅保存身份，不把祖先描述、别名或属性重新包装为新事实。别名在有效实体版本之间合并，各自仍受原始证据约束；别名用于召回，不据此将新事实中的名字自动重写为另一个实体的规范名，以免旧别名纠正后留下错误身份关联。

## 修改、删除与整理

图谱召回会核对支持记忆是否仍在当前故事的有效范围内、是否被当前可见版本替代、正文是否与提取时一致；消息也必须仍存在、active、指纹一致且仍处于下一轮用户消息确认的范围。删除确认消息后不再召回尚未重新确认的尾部事实。不满足时停止召回，无需额外模型调用或依赖 ChromaDB 同步完成。

记忆整理只压缩召回表示，原卡及其来源仍保留，因此被有效整理结果收起的原卡可以继续作为图谱证据；真正的版本替代、人工改写或删除会使相应证据失效。图谱不会绕过记忆原卡和整理产物的只读保护。

这是一种保守失效策略，不会自动根据人工修改后的记忆重新生成图谱；依赖多张卡的记录可能因其中一张变化而暂时缺失。单独手动新增的记忆也不会自动生成实体或关系。

**旧图谱没有可靠的来源信息，保留存储但不进入 Prompt。**已有记忆卡和会话数据继续使用原有路径；后续新提纯生成有证据的图谱记录。本次未提供旧图谱的自动补源或重建工具，不能根据创建时间猜测消息来源。

降级移除新增字段与索引，保留图谱历史行；旧版服务没有新的证据与版本筛选能力，回退后不具备本修补提供的隔离保障。

## 事实共源与联合检索首版

首版沿用 `MemoryChunk.id` 作为事实 ID，不另建一份可独立修改的事实正文。自然语言卡是 SQLite 主记录；图谱和 ChromaDB 向量是检索表示。现有 `supersedes_id` 继续表达分支内的替代，不全局删除旧记录。

聊天通过 `joint_retrieval.py` 执行：

1. 只做一次向量查询，按 SQLite 有效视图复核命中卡，把合法事实 ID 作为图谱种子。
2. 图谱结合名字/别名和种子，沿已有的一至两跳规则返回支持卡 ID；消息与记忆证据仍需通过校验。问题没有写出实体名时也能从语义种子扩展。
3. 回查 SQLite 原卡。整理收起的原卡映射回有效摘要，不重新注入压缩前内容；有效实体定义即使没有关系边也可回查支持卡。
4. 语义命中优先，图谱关联随后补充；按 ID 及规范化正文与时间语义去重。共用最多 16 张、累计 6000 字符预算（包含每卡 80 字符标签预留），超出跳过整卡，不截断事实。目前是确定性次序与字符预算，尚未训练相关性重排或使用精确 tokenizer 预算。

最终都放入动态 `<recalled_memories>`，不把同一事实的图谱描述再放进 `<factual_relationships>`。旧图谱格式化函数保留，聊天使用结构化回查结果。向量没有命中时仍可按名字/别名走图谱；两路均无结果就不补写猜测。

联合结果保留语义召回的 `turns_passed`；仅由图谱补充的卡复用当前分支有效用户轮数计算，排除分叉后的父线未来、非 active 消息与重复复制的分叉边界。客观事实沿用语义召回的零轮次约定，Prompt 继续显示原有远近标签，与故事内时间状态分开表达。

### 故事内时间与来源

迁移 `c8d9e0f1a2b3` 接在证据迁移后，为记忆新增 `temporal_status`、`temporal_note`、`source_evidence_json`。状态为 `current`（明确当前成立）、`historical`（已发生事件/过去状态）、`planned`（计划/约定尚未兑现）或 `unknown`。时间说明最多 120 字符，保留“下个月”等原文语义；不按服务器日期换算或自动认定兑现。Prompt 显式标注计划与故事时间，写入时间不等于故事发生时间。

不同时间状态或说明的卡不走 same/replace 快捷合并；图谱同一边的不同时间语义并存。整理预览与应用拒绝混合时间语义，相同语义保留到摘要；来源快照及增量扫描指纹包含明确时间语义。这是保守策略，可能保留更多卡，不能自动识别所有状态变化、事实纠正、取消或计划兑现。

新自动卡保存消息的角色/正文指纹。两路最终注入均检查来源消息还存在、active、内容一致且已确认；整理摘要继续检查原卡来源。历史回合的替代和图谱均按当前消息截止解析，后续替代不会提前遮住旧卡。旧卡及手动卡无来源快照时保留兼容行为，不伪造指纹或时间；普通记忆列表字段不变，整理来源快照可附带可选时间字段。

### 后续边界

本版仍以卡为事实单位，实体按名称和有证据的别名匹配。稳定实体 ID、多份可独立失效的证据组、角色各自知情范围、自动历史重建与预览、完整故事时间区间及语义冲突裁决尚未实现。修改卡片不自动重新抽图，旧图谱仍保留但不进入 Prompt。真实模型的相关性、重复率和角色表现需要用实际故事评估。
