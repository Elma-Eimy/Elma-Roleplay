# 会话上下文压缩

单聊按故事线保存滚动摘要，用自然语言概括较早对话。摘要与未压缩的原文一起提供给聊天模型，不依赖向量检索命中，不进入长期记忆列表、统计或图谱。群聊目前仍使用原有个人可见上下文，未接入这套压缩流程。

## 自动更新

真实聊天准备 Prompt 时，按 `context_history_limit` 留出最近原文窗口，当前用户消息计入窗口。窗口之外累计至少 4 条未压缩消息时，用“上一版摘要＋这批原文”调用现有记忆模型生成新摘要。只处理严格早于本轮用户消息的 active 用户或助手消息，不接收当前回复、其他候选、推理文本或检索结果。

每次聊天最多执行一次压缩，最多处理 30 条原文，按完整消息累计约 24000 字符；单条消息超出预算时仍完整传入，不截断原文。摘要提示词建议约 1200 字符，程序拒绝空结果、超过 4000 字符或未正常结束的响应。辅助模型与思考设置沿用记忆模型配置，压缩等待最多 30 秒，不依赖长期记忆提纯进度。

新摘要提交前，旧版本继续有效。调用失败、超时、来源变化或压缩输出不合格时，不推进覆盖范围；尚未覆盖的原文继续进入聊天上下文，下次真实聊天重试。因此批次不足、积压或持续失败时，实际原文可能超过设置窗口；首版不通过静默截断来限制这部分内容，也不保证长期失败时仍满足模型上下文上限。

摘要使用独立的 `<context_summary>` system 背景块，固定放在最近原文之前，明确它描述较早消息，后续原文与当前输入承接最新剧情。查看 Prompt 和读取压缩状态都不会调用模型或产生压缩写入。当前可通过 Prompt 预览查看实际注入内容与“上下文摘要”Token 分区，尚无单独的摘要编辑界面。

## 来源、版本与分支

SQLite `context_checkpoints` 保存摘要、模型、覆盖条数及来源前缀的 SHA-256。读取时核对有效消息的 ID、角色、正文及展示状态；编辑、删除或候选变化使相关版本停止注入，优先回退到仍有效的较早版本，缺失部分回到原文。重新生成严格使用本轮用户消息之前的上下文，不读取旧回复结果。历史消息本身不会被压缩功能修改或删除。

调大最近窗口时，读取会回退到不覆盖该窗口的有效摘要，把仍保存在当前故事及冻结基线中的原文重新放回 Prompt，不需要重新调用模型。历史版本继续保留；已经只以父线摘要冻结的更早内容不会被猜测还原。

创建分支时，`SessionPersona.context_base` 冻结分叉点之前的有效摘要和未覆盖原文；所选消息仍由原流程复制为子线首条消息。从非激活助手候选分叉时，基线最多包含该轮用户输入，排除同轮其他候选。父线后续改写和删除不会回写子线。旧分支首次真实聊天时按已有合法分叉边界冻结基线，缺少可信边界时不猜测继承内容。

压缩 API 调用期间不持有数据库事务。返回后在短写事务中复核消息前缀及摘要版本，竞争或来源失效时拒绝旧结果；取消不提交模型结果，沿用聊天回合的失败清理与会话锁释放。

迁移 `c0d1e2f3a4b5` 增加可空分支基线和版本表，不改写旧消息，不在升级时调用模型。删除会话同时回收版本；降级移除压缩版本及基线，保留会话和聊天原文。

## 验证与限制

离线覆盖见 `app-backend/tests/conversation/test_context_compression.py`，迁移回归见 `app-backend/tests/infrastructure/test_context_compression_migration.py`。固定响应只能验证覆盖、隔离和事务，不证明摘要保真。真实模型仍可能遗漏细节，反复摘要也可能产生信息漂移；保留原文与历史版本便于定位，不把简单试跑当作长剧情质量验收。

2026-11-14 使用配置好的模型和独立临时库完成两次增量压缩。首次接续暴露摘要后置导致旧阶段干扰；改为摘要先于最近原文后，同一输入的两次真实复测均承接“明天再测试”的最新安排。原始失败、响应和代码指纹保存在 Git 忽略的 `docs/local/context-compression-tests/`，本次只覆盖一个虚构修表场景。
