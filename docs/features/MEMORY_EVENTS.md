# 进行中事件与长期记忆写入

自动提纯仍按已确认消息数量触发。触发后，稳定事实、偏好、明确承诺和重要关系转折可以直接写入；尚在展开的同一次事件先进入 SQLite 的 `memory_event_buffers`。后续提取能看到事件摘要，补充原事件，而不必每批新增一张长期卡。

## 提取与收尾

模型在事件卡上返回 `event_status` 和 `buffer_id`。`ongoing` 表示继续缓冲，`complete` 表示事件结束；更新已有事件时引用输入中的整数 ID，新事件使用 `null`。只返回本批新进展，程序追加已接收片段，不让新一批摘要整体覆盖旧内容。旧输出缺少这些字段时按完整卡兼容，独立完整卡仍走普通写入查重。

模型不能自行给新事件编号，也不能用记忆数组下标充当事件 ID。事件卡若返回越界或非整数 ID，按相同对话输入附上可引用 ID 列表纠正一次；再次失败继续保留捕获重试任务，不猜测原本想引用哪个事件。非事件卡多余的 `event_status/buffer_id` 按无关字段忽略，不读取对应事件，也不改变卡片类型或来源范围。日志仅记录原因码与允许 ID 数量。

例如，海边约会、下雨转到咖啡馆、谈心后结束约会，分别跨越三次提取。前两次更新同一缓冲，最后一次写成包含起因、转场和结果的事件卡。明确的“明年再来海边”承诺可以单独按 `planned` 保存，事件收尾不会将计划改成已经发生。

事件缓冲有固定边界，当前没有单独的设置界面：

| 边界 | 行为 |
| --- | --- |
| 最多 3 个有待写片段的事件 | 超出时为最早创建的事件生成阶段快照，保留 ID |
| 累计 3 个成功处理批次 | 保存阶段快照并重置批龄；未提及的活跃事件也累计批次 |
| 来源达到 60 条消息 | 保存阶段快照；加入当前完整批次后检查，不截断证据 |
| 拼接正文超过 500 字符 | 先保存旧片段，新片段继续使用同一事件 ID |
| 场景结束、明显转场或话题切换 | 模型返回 `complete`，保存最后阶段并关闭事件 |
| 手动提纯 | 保存有待写片段的阶段；没有新消息时无需调用模型；保留事件身份 |

事件行是持久身份，其整数 ID 保存在阶段卡的 `memory_chunks.event_id` 中。状态为 `open`（有待写片段）、`checkpointed`（阶段已保存，可继续）或 `closed`（事件已结束）。阶段快照追加写入，不调用关系模型替换旧阶段，也不把计划改为已发生。自动查重不能替代已有阶段卡；手动整理同一事件的阶段时保留 ID，不同明确 ID 的事件禁止合并。独立完整卡和普通事实仍走原有查重流程。创建分支时只保存已有阶段，不额外调用模型。

聊天和提取通过动态背景 `<ongoing_events>` 最多接收八个有效事件，优先有待写片段的事件，其余按最近阶段来源选择。每个摘要最多约 500 字符，包含 `buffer_id` 与 `stage_status`。只查询活跃缓冲和最近八个已存阶段的身份，不扫描全部已结束事件。待写片段不进入长期统计或向量库，阶段卡写入后按普通长期卡参与统计与检索。重启后可沿用原事件 ID，已结束 ID 不能重新打开，也不能跨故事引用。

提取增加内部字段 `retention=state/episode/transient`，分别表示持续事实与约定、独立事件与转折、仅属于当前场景的反应。重要性分数用于排序，不能单独决定新建长期卡。新条件、承诺、否定和关系边界应作为持续信息独立保留；没有新增信息时允许返回空数组。

明确的 `transient` 片段可用 `event_index` 引用本批 memories 数组中的事件下标，不能填数据库事件 ID。程序在时间相容、引用有效且完整正文不超过 500 字符时保留片段全文并入事件，扩展支持消息范围、继承最高权重并重映射图谱下标，不再受 28 字和低权重限制。未提供关联时，只有唯一事件完整覆盖来源范围才归入；无效或歧义引用、不同时间及超长片段分别保留，不靠丢弃内容减卡。

旧格式缺少 `retention` 时，保留低于 0.55 且规范化后不超过 28 字的情绪吸附兼容规则。显式 `state` 不走该规则。同批指向同一有效 `buffer_id` 且时间相容的重复事件更新仍预先归并。

片段只在拼接正文能完整容纳时吸收。同批同 ID 的超长片段依次生成同一事件的阶段；情绪拼接超长则保留独立情绪卡。不会截断已接收片段来减少卡数。追加可能保留模型重复表述，不能据此承诺最少卡数。

## 来源、事务与分支

每个事件属于本故事的 Persona，保存当前阶段摘要、故事内时间状态、消息指纹和图谱候选。跨批次更新允许时间状态从 `unknown` 收敛为明确状态（如 `historical`/`current`）或补充此前缺省的 `temporal_note`，但拒绝与 `planned` 跨界或互斥时间状态/说明的混写。阶段卡分别保存自身完整来源指纹，新阶段不再将旧阶段来源扩展成一个无限增长的范围；无待写片段时用最近阶段来源检查身份上下文。

事件本身的来源被修改、删除或切换为 inactive 后，该阶段停止注入和发布，下次处理时关闭失效身份。图谱辅助来源独立校验，辅助消息失效只移除相应图谱候选，保留自身来源仍有效的事件。不会用已经失效的摘要生成新记忆，也不会自动重新提取此前已越过接收指针的旧消息。

已存阶段的身份背景还会检查对应阶段卡是否存在、正文是否一致；人工改写或删除阶段卡后，不会继续注入身份里保存的旧正文。正在积累的新阶段按自身来源独立检查。

主提取调用在事务外完成。模型输出规范化后，候选与接收指针在短事务中原子保存到 `memory_extraction_jobs`，接收指针不再代表长期卡已提交。图谱引用的候选组成依赖组件；同批事件共享容量决策，因此归入同一组件，其他无依赖事实可独立提交。

每个组件先读取快照，在纯内存中规划事件更新；向量查询和关系模型调用期间没有数据库事务。完成判断后，在短写事务中复核任务租约、消息指纹、旧卡与缓冲版本，将事件、长期卡、图谱、Outbox 和任务完成状态一起提交。单个组件失败不会回滚其他已提交组件，任务保留候选等待重试；成功任务清空候选正文，仅保留状态与计数。

独立记忆 Worker 每五秒检查到期任务，使用退避与可恢复租约；同故事部分唯一索引保证同时最多一个处理任务，token 防止过期处理者提交。它与向量 Outbox 分开运行，服务关闭等待正在执行的线程释放自己的数据库会话。主提取失败也会登记捕获重试任务；恢复后无需新消息即可继续接收积压。此 Worker 不按闲置时间主动结束事件，停止聊天后可以手动提纯收尾。

HTTP 手动提纯和回合维护只可靠登记捕获请求，不等待模型；手动接口返回当前队列状态，新增数量保留字段为零，完成结果通过记忆列表与日志查看。离线 Mock 明确不执行提纯，不虚报生成数量。

聊天动态背景另提供最多八张有效待处理候选，标明可能重复、尚未整理，避免接收指针推进后立即失去上下文。关系模型接收完整时间语义与来源边界；正文相同但时间更明确时保存新版本，补处理较早消息不得覆盖较晚来源支持的当前卡。

写入比较先判断是否只是同一持续状态的重复表达，不能仅因为两段话都能成立就选择共存。近期十二张候选由 SQLite 补入，向量检索只查询更早的同类型、相容时间卡；阈值外仍补入最多两个最近邻，最多返回六个向量候选。原距离阈值控制额外候选的纳入，不再是全部候选的硬门槛；接受候选不表示允许归并。

关系模型在 `replace` 时可返回 `change_kind=refinement/correction`。相容补全按原文追加旧卡和新卡，避免整体重写漏掉旧条件；拼接超过 500 字符就分别保留。补全以及仍携带旧细节的部分纠正，会合并本故事中已验证的旧、新消息指纹；明确取消且当前正文完全由新卡支持时只使用新来源。不把祖先或无指纹旧卡伪装成本故事消息证据，证据不足则分别保留。省略 change_kind 的旧输出保留原流程兼容。

这仍使用现有候选与版本机制，没有新增永久事实槽位表。模型可能误判持续状态、即时反应或需要保留的细节，长期问答与全面语义保真仍需真实样本验收。

分叉时只保存来源完整落在 `fork_message_id` 之前或等于它的有效父故事阶段，让子故事通过现有长期记忆视图继承。跨越分叉点的摘要包含未来信息，既不发布，也不复制给子故事。分叉与阶段保存共用创建会话事务，失败一并回滚。父故事继续沿用自己的事件 ID；子故事不继承可写身份，后续提取使用子故事独立身份。

图谱候选随阶段暂存，在阶段卡写入后发布。已接收的旧片段及其图谱依据随当前阶段保留，发布后清空待写来源与图谱，新阶段独立积累。当图谱项同时引用事件与本批其他卡片时，仍通过证据绑定（`_extra_bindings`）校验全部关联卡；未落库的依赖不会被降级为单卡。跨阶段身份本身不代替图谱证据。

## 日志与验证

容量收尾时，本批释放的图谱候选与仍在缓冲的候选都在长期卡写入后解析跨卡依赖；未落库依据不会被忽略后按单卡发布。混合字符串、对象或布尔值的非法图谱下标安全拒绝，合法记忆与图谱项可继续提交。

`[MEMORY EXTRACTION] committed` 记录任务 ID 和 `new/replaced/reused/written`；重试使用 `job_deferred` 与原因码，分叉保存阶段使用 `event_flushed_for_fork`。实际写入以任务提交日志为准，阶段归属可在 SQLite 的 `event_id` 中核对。独立完整卡仍可能通过查重复用。日志不打印事件正文或模型原文。

表结构由 `a2b3c4d5e6f7_add_memory_event_buffers.py` 迁移建立。回退该迁移会移除待处理事件表，已经写入的长期记忆保留；旧库升级不会改写现有记忆。

候选任务由后续迁移 `a3b4c5d6e7f8_add_memory_extraction_jobs.py` 建立。回退候选任务迁移时，仅将仍有未完成候选的故事接收指针退到最早待处理来源之前，让旧代码可以重新提取；已提交的长期卡保留。

`a4b5c6d7e8f9_persist_event_checkpoints.py` 增加事件状态与阶段卡外键。旧缓冲按 `open` 升级，旧卡身份保持为空，不猜测历史归属。回退会删除无待写片段和已结束的身份，移除阶段关联字段，保留所有长期卡正文；已存在的活跃阶段可交给旧代码处理。

离线回归见 `app-backend/tests/memory/test_memory_event_buffer.py`，覆盖跨批次合成、时间状态收敛、瞬时伴随情绪吸附、跨卡图谱绑定、直接写入的事实与承诺、缓冲上限、重启与手动收尾、图谱事务、来源失效、并发版本及分叉隔离。迁移回归见 `app-backend/tests/infrastructure/test_memory_event_buffer_migration.py`。这些测试不调用真实模型；场景识别和摘要保真仍需实际对话验收。

固定虚构对话见 `app-backend/tests/fixtures/event_retention_cases.json`，回放入口为 `python -m tests --group memory --pattern test_event_retention.py`。八批赠书与四批修表分别检查八项、四项事实线索，覆盖归属、金额、否定、原因和承诺条件；每批响应只保留新进展，最后一批故意不复述旧细节。测试检查跨阶段、重启后的事实线索保留与身份一致，并用“仅保存最后一批”作为失败对照。指标是已提取片段的字面线索保留率，不是模型首次提取召回率，也不能自动判定否定、因果或承诺语义正确。

当前仍有边界：超过背景预算的久远事件身份不会自动注入，模型漏引用 ID 仍可能另开事件；旧格式完整卡不会自动追认事件身份。新摘要也可能编造或错误解读新消息，需要以固定样本和脱敏真实对话继续人工验收。历史阶段可以通过长期检索召回，但本版没有新增按事件分组的前端展示。
