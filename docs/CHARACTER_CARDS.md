# 角色卡导入与参考规范

## 社区规范

- [Character Card V2 原始规范](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)：V2 使用 `spec`、`spec_version` 与 `data` 封装，包含备用开场白、作者信息、扩展和可选世界书。第三方扩展应保留。
- [Character Card V3 原始规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)：PNG/APNG 的 V3 数据使用 `ccv3` 文本块；同时存在 `ccv3` 与 `chara` 时，V3 实现应优先采用 `ccv3`。

本项目目前支持 PNG 的 `chara` 元数据与 V1/V2 风格 JSON。读取 `tEXt`、`zTXt`、`iTXt`，兼容 Base64 JSON 与原始 JSON 文本。尚未完整支持 CCv3、CHARX 及其资源、昵称和群聊开场白语义，不应把读取部分共有字段视为完整 V3 支持。

## 导入流程

1. 从首页或画册的导入入口直接进入导入面板；也可以在创建、编辑或人物档案中选择导入。H5 选择 PNG/JSON 文件，App 从相册选择原始 PNG，微信小程序使用聊天文件选择器。
2. `/characters/parse` 校验扩展名与上传大小，在临时目录解析文件。有效 PNG 以完整文件的 SHA-256 命名并保留为头像，相同内容重复解析复用该文件。JSON 和解析失败的文件不会写入头像目录。
3. 导入面板显示人物、作者与版本、开场数量、标签和内嵌世界条目，并提供人物设定、故事开场、作者说明与内嵌世界的预览。确认前不修改当前草稿或角色记录。关闭面板会使晚到的解析响应失效。
4. 应用到已有内容时可选择替换设定或仅补充空项。替换会清除旧卡的设定和内嵌世界书，使用新卡内容；补充模式保留已有非空文字、非空数组及扩展值，只补充空项。JSON 更新已有角色时保留原头像。
5. 创建、编辑页先应用到草稿，保存后才写数据库；人物档案的导入更新在预览确认后直接保存。页面复用解析返回的 `avatar_path`，不再次上传 PNG。同名创建通过响应的 `created: false` 提示打开已有档案或继续修改姓名，不再静默使用已有角色开启故事。
6. 新角色可以只存入画册，也可以先选择开场再保存并开启故事。故事创建失败后重试会复用本次已创建的角色，避免再次新建角色记录。

解析接口本身不写数据库；成功解析但未保存的 PNG 仍可能成为未引用资源，本次不增加自动清理此类文件的策略。

## 人物展示与开场管理

- 详情页优先展示场景摘要、作者与版本、折叠标签和故事/世界条目数量。人物档案包含作者说明、背景、性格、场景、原文提示词与全部开场白。
- 开场浏览支持搜索、每组六项分页和选中后的全文预览；展示、搜索不会改变后端 `greeting_index`。默认开场使用 `null`，备用开场使用原数组索引。
- 编辑页可逐个编辑、添加和删除备用开场；修改保存在 `extensions.alternate_greetings`，不会修改既有故事消息。
- 长文阅读每页最多 3000 个 UTF-16 代码单元，避免初次渲染整篇作者说明；提示词与示例按原文展示，保留宏和结构标签。Markdown 不执行 HTML，也不加载卡内远程图片。
- 从现有剧情分叉时延续剧情，不展示独立故事的开场选择。
- 作者、角色版本和来源格式保存在 `extensions.ai_roleplay_card` 中，沿用现有创建/更新与详情接口持久化，无数据库迁移。此前已导入且没有该信息的记录，可通过重新导入原卡补充。

同一 PNG 的多个有效 `chara` 块按文件顺序保留；产品导入沿用首个有效块，后续副本不覆盖它。此选择是项目兼容策略，并非社区规范定义的重复块优先级。不要拼接不同块的字段，以免混用不同角色版本。

解析会校验角色对象、非空名称和字符串数组，支持带 UTF-8 BOM 的 JSON。归一化在副本上执行，不修改原始对象。展示字段仍沿用 HTML 转 Markdown；Prompt、示例和世界书正文保持现有 DSL 处理规则。归一化响应并非原始卡的无损备份。

## 原文与中文阅读版本

导入预览和人物档案提供「翻译为中文」。首次手动翻译，成功后默认显示中文，可随时切回原文；「重新翻译」使用当前配置的翻译模型更新副本。翻译过程不阻塞浏览、确认导入或离开页面。

- 阅读范围：人物背景、性格、场景、默认与备用开场白、对话示例和作者说明。原卡名字、标签、隐藏系统提示词、历史末端指令与世界书维持原文。
- 在「设置 → 模型与引擎 → 辅助任务模型」单独选择翻译模型，未配置时从现有非思考聊天模型初始化一次，使用现有聊天服务连接。可添加模型 ID 后再选择，不跟随聊天模型与思考开关；可关闭思考的模型使用非思考模式。
- 中文副本仅供阅读，绝不写回角色字段、扩展或会话；保存、导出、Prompt 装配和故事开场选择继续使用原文与原数组索引。要求角色用中文回复属于对话设定，不由阅读翻译控制。
- SQLite 的 `character_translations` 表按阅读字段内容与翻译版本的 SHA-256 缓存，支持尚未保存的导入预览；同一原文可复用。原文修改后不再匹配旧译文，需重新翻译；更换头像、隐藏提示词或模型不主动清空已有副本。
- 长文按段处理，保留 `{{char}}`、`{{user}}`、结构标签和备用开场空项；生成截断、响应结构错误或占位符变化时整次翻译失败，不存半成品，也不覆盖上次成功的副本。目前单卡阅读内容上限为 12 万字符。
- 分段采用简单长度映射：ASCII 字符按 0.25、其他字符按 1 计，每段最多折算 2400（纯 ASCII 最多 9600 个字符，纯中文最多 2400 个字符）。每批最多三段且原始文本合计不超过 9600 个字符，保留占位符完整性与原始顺序。该映射不是精确 Token 数；每批模型输出上限提高至 32768 tokens，单卡 12 万原始字符上限保持不变。
- 分段边界的空白与换行由原文恢复，避免模型裁剪首尾空白后把段落粘连。缓存采用 v2 翻译版本，旧版本缓存仍保留但不再自动匹配。用户在请求期间手动切换阅读语言时，迟到结果只更新副本，不覆盖阅读选择；切换服务器后不接受上一服务器的响应。
- 查询缓存不会自动调用模型；离线 Mock 明确提示不支持在线翻译，不生成虚假中文。前端请求最长等待 10 分钟，实际还受供应商与部署网关超时限制。

API 请求与返回结构见 [API 总表](../API_TABLE.md)。缓存独立于角色保存与删除，预览未导入、原文旧版本以及删除角色后的缓存也会保留，便于同卡再次导入；不会作为 Prompt 或检索资料使用。

## 无损 JSON 导出

在 `app-backend/` 执行：

```powershell
.\venv\Scripts\python.exe -m scripts.export_character_card <原始PNG路径> <输出文件夹>
```

命令不连接数据库，为每个有效 `chara` 块生成独立的 `.chara-1.json`、`.chara-2.json` 等文件，不清洗字段或覆盖已有输出。它保存 JSON 数据的原始结构和值，不保留 JSON 空白排版或 PNG 二进制块。

本次用户提供的本地参考卡有两份有效 `chara` 数据；第一份含内嵌世界书，第二份不含。两份均包含 39 条备用开场白和较长的作者说明。原卡、导出 JSON 及资源清理备份仅保留在本地，不作为自动测试夹具提交。

## 历史重复资源清理

仅按完整文件 SHA-256 判定相同内容，不按文件名或视觉相似度删除。保留当前 SQLite 文本字段中引用的文件及用户指定的参考原图；删除前逐个备份并校验副本，清单保存在 `docs/local/avatar-cleanup-2026-10-20/manifest.json`。本次未修改角色记录或会话数据，也未删除无重复副本的其他文件。
