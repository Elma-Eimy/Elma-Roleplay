# 多立绘与 CHARX 角色包待办

记录日期：2026-10-21。状态：需求留档，暂不实施；本文是后续讨论依据，不代表已支持的功能或最终接口设计。

后续进展：聊天页已先使用现有单张角色图片增强居中背景，消息、顶栏与输入区叠在同一画面，详见 [前端说明](../app-frontend/README.md#聊天背景)。CHARX 导入、多图片管理及剧情联动仍为待办，下面的差距描述保留为需求记录时的基线。

## 目标

支持同一角色携带多张表情、服装或姿势立绘及配套信息，在聊天中展示与切换。优先考虑导入社区已有的 CHARX 角色包，同时允许普通 PNG/JSON 角色手动补充图片。

## 已查证的格式与当前差距

- CHARX 使用 `.charx` 扩展名，本质为 ZIP；根目录 `card.json` 保存 CCv3 角色数据，`assets` 清单引用包内素材。普通 ZIP 是否接受，应按内容识别策略另行确定，不能把任意压缩包视为角色包。
- 标准资源类型包括头像 `icon`、表情 `emotion`、背景 `background` 等；表情可通过名称标识。服装、姿势和剧情差分的自动切换不能仅靠格式保证，需检查实际样本及平台扩展。
- RisuAI 支持表情图片展示，其角色卡导入代码会分别处理表情与主头像。支持 CHARX 容器不等于完整兼容 RisuAI 的脚本、模块和自定义界面。
- 项目当前选择器仅接 PNG/JSON；导入服务主要保存单个 `avatar_path`，聊天角色背景也引用同一头像，尚无独立的多立绘资源管理与切换链路。现有格式行为见 [角色卡导入](CHARACTER_CARDS.md)。

## 建议分阶段范围

1. 样本核对：选取实际使用的角色包，检查卡片版本、资源清单、命名及平台扩展，确定首批兼容范围。
2. 导入与管理：支持 CHARX 设定及图片预览，分别管理头像、背景、表情立绘；支持默认图、手动补图与未支持内容提示。
3. 聊天展示：沿用居中立绘背景与消息叠放的布局，增加多立绘手动选择与切换；尝试将现有情绪标签映射到表情资源，无法匹配时使用明确的默认策略。图片裁切与具体切换效果在实现前确认。
4. 剧情联动：候选切换、重新生成、删除与分支恢复遵守对应消息边界，不将其他候选或祖先未来的立绘选择带入当前剧情。
5. 后续扩展：依据样本需求考虑服装、姿势、剧情差分及平台专用规则，首版不承诺完整脚本运行兼容。

## 实施时需要解决的问题

- 素材引用与持久化、去重、导入取消后的资源处理，以及删除时沿用 Outbox 回收机制；如新增数据结构，同步 ORM 与迁移。
- 压缩包路径与解压大小校验，资源类型和引用解析；不自动执行包内脚本。
- 情绪名称映射、多人物归属、手动选择与自动切换的优先关系。
- 三端文件选择与显示适配，尤其 App 当前相册入口不能直接承接角色压缩包。
- 使用独立样本与测试数据验证导入、默认图、缺失资源及剧情边界；按项目约定执行相关回归与三端构建，真机效果另行验收。
